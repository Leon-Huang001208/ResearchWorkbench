# PR245 Python CI 双 job 分片：本地候选

宿主为 macOS；任务类型是既有 Research Web CI 容量修复，仅修改 PR245 feature worktree 的 workflow、stdlib runner/stager、相邻单元测试及对应验证文档／08 图源。源 HEAD 为 `717826b44b6b7a8fbbe9c1f50f89d07cdba6903b`。`git_safety.mjs check` 对控制 checkout 实测 `fsck=PASS`、`nativeLocks=[]`、`repositoryLocked=false`。没有提交、push、PR 更新、rerun、workflow dispatch、模型／供应商调用、服务变更或依赖安装；repairAttempts=3 与旧失败回执不变。

## 设计

- 原完整 Python selection 在每个 job 中先收集同一 ordered node 集合，再以 `suite[index::2]` 形成两个 job shard；每个 job shard 继续用原 runner 的两个 worker 做第二层确定性轮询，所以同时最多两个 Ubuntu job／四个 pytest worker，单 job 仍为 45 分钟。
- 原 required job ID `checks` 改为统一门：下载两份独立 artifact，要求两个 job shard 是原 collection 的精确、无交叉并集，并逐 worker 核验 final、退出码、执行 node、脱敏 JUnit、artifact JUnit 摘要与真实 `passed`。缺 shard、final、JUnit 或任何非 PASS 都失败。
- JS/editorial 只在 shard 0 执行一次并放到 Python 前；先前普通失败时仍继续后续合同，取消时不通过 `always()` 强行启动大测试。最终 `checks` 同时要求 matrix job 结果为 success，避免 Python 证据绿掩盖 JS/editorial 失败。
- staging 不再打开原始 `pytest.log`。没有 final 的 worker 也不打开可能仍在写的 JUnit，只读取原子替换、字段封闭的 progress；progress 仅供取消诊断，统一门仍因缺 final/JUnit 失败。已有 final 时继续按 owner/root/plan/worker/JUnit 严格核验并生成脱敏 artifact。
- 最终 gate 要求两份下载物都带完整 `status.json`、`research-web` 与 `unit`。artifact 根、scope、worker 和文件复用 owner/device/inode 绑定 dirfd、`O_NOFOLLOW`、单链接和 100 MiB 门；held fd 覆盖读取与语义验证，成功前重开根路径复核，拒绝根／中间／文件 symlink、hardlink、inode swap、缺 scope 与超限。
- 验证拓扑属于真实结构变化：08 图源新增“双 Job 合同执行 → 统一 checks 门”，架构 map 将该边绑定 workflow 与 stager；四份 verification-workflow 模块文档同步相同事实。资源恢复后已用正式 Archify 入口重新 deliver HTML／receipt／visual receipt，并实际查看明暗四张截图后更新同哈希人工记录。

## 新增回归范围

- job shard 的确定性、无交叉与精确并集；workflow 的两个 matrix shard、每 job 两 worker、单一 `checks` 门和 JS/editorial 顺序。
- 取消时缺 final 只取 progress，禁止打开 live pytest/JUnit；缺 worker final、缺 JUnit、错误 union 必须被最终门拒绝。
- 两份完整小 artifact 的 final/JUnit/worker 归属与跨 job union 正例。
- 生产默认双 scope 的两份 download 布局经 CLI `--verify-shards` 的正例，以及缺 root/scope/final/JUnit、改 JUnit、跨 scope index、不同 selection、重复 shard 的非零负例。
- workflow 结构合同固定两个 job ID、matrix `fail-fast: false`／`max-parallel: 2`、JS/editorial shard0-only、唯一 artifact 名、双下载路径与 matrix-result guard，并有四类删除/冲突变体的 RED 定义。
- 最终 artifact 路径安全合同覆盖 root/file/intermediate symlink、hardlink、open 时 inode swap、size bound 与有效 held-fd 正例。
