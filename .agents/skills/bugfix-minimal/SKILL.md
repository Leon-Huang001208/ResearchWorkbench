# Minimal Bug Fix

以可复现的失败锁定回归，再以最窄改动修复它；“看起来相关”的清理不是修复范围。

## RED：先复现，再编辑

1. 阅读根目录 `AGENTS.md` 以及故障区域的直接规则、测试和最近改动。
2. 在任何实现编辑前，固化最小失败复现：输入、期望、实际结果与运行命令。新增或更新离故障最近的回归测试，并确认它因该缺陷失败，而不是因环境、拼写或不相关问题失败。
3. 从复现沿数据/调用路径查找第一个错误条件、映射、优先级或回退；把它写成可证伪的最窄根因假设。

## GREEN：最窄修复

- 仅修改使该回归测试通过的根因位置及必要测试。
- 不重构无关代码、不迁移架构、不顺手格式化邻近模块；若发现另一问题，单独记录，不把它塞进当前补丁。
- 修复后运行目标回归测试及适用的相邻测试，并保留实际结果。

## 交付边界

明确分开报告：

| 类别 | 必须说明 |
| --- | --- |
| 已验证修复 | 失败复现、根因、改动、回归测试与实际命令结果 |
| 未验证假设 | 未运行的组合、外部依赖、环境限制和仍待确认的产品语义 |

没有编辑前的失败复现、最近回归测试，或目标测试失败时，不能声称修复完成。

## 防错检查

“先改再补测试”、“既然定位到了就一起整理”或“测试应该能过”都不是证据。撤回到最小复现和最窄根因，避免以大重构掩盖故障。
