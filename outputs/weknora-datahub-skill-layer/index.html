1. 结论先行

  1. 问题不是"底层没接"，而是"接了但没有按任务契约化"。已有金融聚合入口通过 ext_finance_mcp 接入 DataHub；目录列出八家，但逐服务发现与契约化仍为 PARTIAL。
  2. 缺的是 vendor 到 RWB capability 的数据契约：字段映射、单位、日期语义、 PIT、分页、错误码和质量门。模型选业务工具；服务端依据已验证契约选源。
  3. 不应把 100+ 个厂商原生工具暴露给模型。WeKnora 只应看到少量任务级工具； capability 与 source 的固定在 RWB 服务端，模型只填业务参数。
  4. 底层契约优先于复合 Skill。首先完成 market_bars 与 get_stock_kline 的完整链路， 再扩展 financials 和 search_announcements；不要求三者同时完成才开放首个工具。
  5. 复合技能（如 market_overview）在底层工具稳定后再做；v1 规划最多 12 个业务工具， 按逐项验收注册，其中新闻检索、公告和用户数据库工具按条件启用。

架构入口：系统总览、 Research Web 分层阅读、 开发地图、数据源清单。

2.4 已知问题

  1. 多数工具使用自然语言入参，例如 iFinD get_stock_performance({query:"..."})。 RWB 必须用结构化参数拼出确定性 query，不能把模型原话直接透传。
  2. 通联两次调用均返回 INSUFFICIENT_CREDITS（实测 2026-11-24，600519 与 000001 各一次）。用户已决定 v1 排除通联，不进入任何路由候选；恢复条件是重新购买 额度，并通过一次真实 K 线取数验收。
  3. 不同厂商同一指标的口径、单位、复权和日期语义未对齐。
  4. 该 MCP 不提供 PIT 证明；正式回测和历史时点研究不能直接采用。
  5. 岗底斯操作名为中文，参数键为 camelCase；其他厂商用英文工具名和不同参数风格。 契约层必须逐厂商适配，不能假设同构。

10.1 设计原则

用户的理解方向正确，但要区分三件事：

  1. 工具写死：模型只看到一个稳定工具和一套稳定参数；capability 与 source 的参数不暴露给模型；工具名供模型选择。
  2. 路由表写死：候选源和优先顺序由服务端固定维护，不是模型临时决定。
  3. 源可维护：接口变更或不可用时改适配器和路由表，不改工具契约。

因此"写死"的是契约和路由，不是写死单一供应商。单源写死会在该供应商限流、 停服或权限变化时直接失去能力；RWB 现有设计是固定候选集 + 固定顺序 + 不跨源拼接。

文档与工具目录按第 4.1 节的 Wind 七域组织；跨域公共工具、用户数据库另列为 RWB 扩展。 域目录不自动注册工具；v1 仍只做已定义且可验收的子集，债券和通用取数域暂不注册工具。 分类目录不要求拆成七个 MCP server，也不改变内部 capability 标识。

简单 K 线请求直接调 get_stock_kline。复杂任务如“今日市场行情”，由 Skill 规定查询哪些指数、涨跌家数、成交额、行业表现与资讯，再调用已经存在的业务工具。 Skill 不能通过说明文字获得缺失数据能力；指数历史和市场宽度工具未实现时必须报告缺项。 WeKnora 能否加载文件型 Skill 仍需单独验证，不能把普通工具说明当作已安装 Skill。

11.3 候选与本地覆盖共同决定来源

  1. 验证账号权限、请求证券、字段、频率、单位、复权及 PIT 约束。
  2. 获取已实现且满足口径的固定顺序候选。显式源请求保留该来源约束。
  3. 对当前候选，按其存储身份查覆盖；全覆盖则直接冻结本地结果，不调用供应商。
  4. 有缺口时检查该源实时就绪，按交易日合并缺口，再按该源调用上限分段。
  5. 只从该源补齐；验证、写仓、重读整个窗口，仍有未知缺口则不算完整。
  6. 当前源失败且策略允许替代时，对下一候选重新执行 3～5。 账号/授权范围拒绝属于整个请求错误，直接停止；不能以换源绕过。

“先查本地”表示不为已有事实重复调用网络，不表示先把所有供应商数据混成一张无来源表。 覆盖身份沿用账号/授权范围、来源与配置摘要、证券、数据类型、频率、单位/字段和语义摘要。 金融聚合入口的身份还必须区分上游 vendor/service；不能把 DM 与岗底斯都只记成 ext_finance_mcp 就认定同源。正式 binding 标识在适配时落实并写进来源元数据。 实时服务离线与授权失效不同：前者不必阻止合法本地读取，后者仍按原权限合同处理。

11.4 覆盖、停牌与增量补齐

覆盖检查使用权威日历和覆盖证明；不能从 max(date) 推定中间日期都完整。 last_complete_date 只能作为加速提示，不是跳过区间检查的依据。

日期状态处理
正常已完成交易日且事实满足字段合同算事实覆盖
有来源可追溯的停牌、未上市证明算证明覆盖，不填造 OHLC
缺行且无证明缺口
今天未收盘最终日 K 查询排除该未完成交易日并记录有效范围；盘中快照另走快照工具
整个窗口均休市日历已确认时返回空且无缺口；日历未知不能当作完整空结果
历史值被供应商修订显式 refresh 重取；普通缺口补齐不保证发现既有日期修订

真实 CoverageProof 字段为 business_date / state / evidence_id / available_at， state 为 suspended / prelisting / nontrading / unknown。不新增虚构的 reason/source_digest 字段；来源与授权身份位于现有存储上下文。unknown 不算覆盖。

缺口按交易日序列合并：周五、周一都缺则是一段；中间有已覆盖交易日则分开。 超过现有 16 段阈值时保留现行折叠规则；折叠后仍按源窗口拆分， 返回重叠数据时沿既有一致性校验，不能绕过冲突处理。

11.5 原始数据、复权与快照

复权仓库目标为不复权价格及真实量额，加同来源的因子/公司行为数据； 不是宣称当前全部 provider 已能产出该存储形态。现有已存数据不迁移或删除。

只对已验证为兼容乘法因子的来源使用下式，其他模型交给相应适配并单独验证：

qfq(t, base) = raw_price(t) × factor(t) / factor(base)
hfq(t, origin) = raw_price(t) × factor(t) / factor(origin)

同时记录因子来源、版本、基准日、公式版本、原始价版本；raw 与因子不能随意跨源。 读取时生成复权视图；冻结查询结果仍可保存复权行作为证据，不当作无版本的仓库事实。 as_of 是历史可知时间，adjustment_base_date 是价格缩放锚点，二者严格区分。 PIT 查询继续走已验证的时点读取路径，v2 不把实时源当作历史可知数据。

11.6 输出与复用边界

沿既有查询幂等、任务状态、分页与冻结快照链。manifest 记录实际来源、有效区间、 单位、缺口、证明摘要、复权元数据及有界计划摘要。无需创建另一套取数作业和状态服务。 快照可用不等于 PIT 已验证；供应商调用成功也不等于完整字段和覆盖通过。

查询服务、MCP 和脚本共用同一执行逻辑，避免将业务校验和缺口算法各复制一份。

11.7 一条链路的验收范围

首条链路为沪深 A 股日频不复权 K 线；复权能力分源验收后启用。 全命中零供应商调用；部分命中只补同源缺口；换源重新规划； 单段不超供应商限制；空窗口、停牌和失败不会被伪报为完整价格序列。 先通过这一条链路，再扩展财务、公告和其他工具。
