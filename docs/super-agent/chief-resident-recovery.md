# 发布回执未知时的核对与阻塞报告清单

适用情形：发布操作已经发起，但回执缺失、超时或状态不明，尚不能确认发布结果。

## 核对原操作证据

- [ ] 记录原操作的目标环境、发布版本或提交标识、发起时间、操作入口及执行人。
- [ ] 保存已有的请求标识、任务标识、流水线链接、日志和错误信息；缺失项明确标记为“未知”。
- [ ] 根据原操作标识查询对应任务、流水线或发布记录，确认记录确实属于本次操作，避免混用其他发布的证据。
- [ ] 检查原操作是否仍在执行、已经成功、已经失败或已被取消，并记录查询时间与证据出处。
- [ ] 核对目标环境实际生效的版本及部署状态；区分“任务执行成功”和“目标版本已经生效”。
- [ ] 对照执行记录与环境状态。证据不一致时保留差异，不凭单条日志或回执缺失推断结果。
- [ ] 在结果核实前，不因回执未知而重复发布；如需重试，先确认原操作状态及重复执行风险。

## 何时报告阻塞

- [ ] 仍能通过现有权限查询原操作或核对环境时，继续核查，不仅因回执延迟就认定阻塞。
- [ ] 原操作仍在运行且未超过既定执行或观察时限时，报告“执行中，结果待确认”，按既定机制继续观察。
- [ ] 缺少关键操作标识，且无法从现有记录定位原操作时，报告阻塞。
- [ ] 因权限不足、查询渠道不可用或必要证据无法取得，无法继续确认结果时，报告阻塞。
- [ ] 已超过既定执行或观察时限，完成可用查询后仍无法确认结果，且没有安全的后续核查路径时，报告阻塞。
- [ ] 执行记录与目标环境状态冲突，现有证据无法消除差异，继续操作可能造成重复发布或覆盖时，报告阻塞。
- [ ] 原操作已明确失败时，报告失败及证据；只有恢复工作也无法继续时，另行说明阻塞原因。

## 阻塞报告必填项

- [ ] 原操作：目标环境、版本、发起时间及可用的操作标识。
- [ ] 已知事实：已确认的状态、证据链接或日志位置、最近核查时间。
- [ ] 未知事项：尚不能确认的结果，以及缺失或冲突的证据。
- [ ] 已做核查：查询入口、查询结果及无法继续的具体原因。
- [ ] 影响：哪些后续步骤无法安全推进，是否存在重复发布风险。
- [ ] 所需协助：需要补充的标识、权限、系统恢复或人工核验，以及对应责任方。
- [ ] 下一步：恢复核查所需条件及后续检查安排；明确当前发布结果仍为“未知”，不表述为成功或失败。
