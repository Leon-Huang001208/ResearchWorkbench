# GitHub 来源准入、去重与原 PR 接续

本页只说明 GitHub Issue 如何成为可核对的任务输入、如何去重，以及如何沿原 PR 接续。三端责任见[统一集成](unified-integration.md)，本人命令和权限见[接入说明](README.md)，执行、独立 QA 与恢复见[生命周期](task-lifecycle.md)。

## Issue 输入模板

提交来源至少写明：

| 字段 | 要求 |
| --- | --- |
| 目标 | 要解决的问题和实际成果，不用标签代替目标 |
| 允许文件 | 明确可修改路径、禁止触及的对象及相关输入 |
| 可观察验收 | 可核验的内容、格式、测试或证据及未执行项处理 |
| 交付终点 | 仅产物、仅 PR 或已明确获准的其他动作，不能留给执行者猜测 |

`agent:ready` 只是准入申请信号，不是运行、合并、部署或提高项目权限的授权。入口须核对真实来源作者、仓库、Issue、项目绑定、任务范围及已有映射。缺项明确记录，不能以标签、转述或快速回执代替本人授权。

## 先查映射，再续接

去重记录包含仓库 fullName、Issue 编号／URL、来源事件 ID、原 Native UUID、原 PR 及完整 head。仓库与 Issue 确定来源身份，事件标识防重复受理，Native UUID 确定原根；原 PR／分支与 full head 用于核对候选版本。head 更新是同 PR 的新候选，不因此建立新根。

1. 收到事件先查映射和原操作；重复标签、重放消息或返回丢失不能重复创建任务。
2. 已有原根则关联输入版本及来源事件，沿原责任和预算接续；结果 unknown 先对账。
3. 已有原 PR 则保留原分支与 PR，获准修订后重绑新 head 的独评和 CI，不另建替代 PR。
4. 无可核对映射时先列出缺项，不凭同名任务或短 SHA 猜测；没有结果不能当作未受理。

必要历史来源保留为 [Issue #262](https://github.com/Leon-Huang001208/ResearchWorkbench/issues/262) → Paperclip LEO-5 → [PR #263](https://github.com/Leon-Huang001208/ResearchWorkbench/pull/263)。此映射用于追溯原目标，不宣告其当前 GitHub 状态、CI 或通知已通过；完整 UUID／head 和历史耗用进入内部证据。

## 当前入口与授权上界

旧 UNIFIED 入口关闭，不承诺添加 `agent:ready` 会自动启动执行。本人通过 `/chief --project rwb new <目标及原 Issue 链接>` 提交来源前，必须先查原 Issue／事件到 Native root／PR 的映射；已有任务使用同根补充或继续，不重复建根。命令语法以[本人入口](README.md#本人入口与项目选择)为准。

普通项目动作上界取可信 Native 项目、catalog 和当前任务许可的交集；登记 GitHub 远端不等于获得源码工作区或写权限。历史 DevOps 合并／部署例外仅绑定其本人明确授权的原任务及受管操作，不成为普通任务的全局权利。旧文档试点“不合并、不部署”只说明其当时终点，不是后续所有任务的永久禁令；具体交付仍按当前有效授权和项目门禁。

## 读取故障与证据边界

Mac 原生任务的隔离 HOME 与宿主 `gh` 认证不同。宿主登录可用不证明任务连接可用；读取失败交 Network Engineer 核对真实通道，不能当作仓库不存在、模型失败或重新执行任务的理由。

登记仓库的获准只读入口为 `host.github_read`，仅限当前 Native 登记仓库及获准只读操作；其读取遵守权威 Super Agent《Native任务的GitHub只读连接》（docs/github-read.md）合同：仅使用当前 Native 登记的仓库身份和获准操作，不复制宿主凭据，不匿名降级，不改全局代理或认证。该文档为来源引用，不是本任务已验证连接的声明。

只读元数据须带来源、观察时间、完整 head；列表截断如实保留。读取 PR 状态不证明 patch 等价、检查通过或部署成功。没有当前读取时，原 PR、head、CI 只按输入时点引用，不能冒充当前状态。unknown 沿原操作核对，具体恢复与证据字段统一见[生命周期](task-lifecycle.md#最小交接字段)。
