# Super Agent 三端责任与证据关联

Paperclip 是唯一任务、运行和会话控制面；GitHub 是源码、PR 与 CI 的事实来源；飞书是本人输入和结果回执入口。三端关联同一任务，不建立竞争任务库，也不以消息回执替代任务成果。

本人命令、岗位、执行环境、预算与权限见[接入说明](README.md)；推进及恢复见[任务生命周期](task-lifecycle.md)；GitHub 来源准入、去重及原 PR 续接见[GitHub 入口](github-intake.md)。本文只说明三端责任，不重复项目政策或历史执行流水。

## 谁保存什么

| 系统 | 权威责任 | 不能据此推定 |
| --- | --- | --- |
| Paperclip | 原 Native root、项目／owner、输入版本、责任人、计划、子任务、run／会话、人工决定和证据引用 | 登记或完成状态不证明源码、CI、部署或通知已成功 |
| GitHub | Issue 来源、源码提交、原 PR／分支／完整 head、检查与合并事实 | PR 存在或 CI 通过不证明业务验收、服务切换或消息送达 |
| 飞书 | 已认证本人输入、补充和对应接收／结果回执 | 快速接收回执只表示收到意图，不是模型成果、QA 或授权扩张 |

控制层只保存授权绑定、操作意图、映射与回执；任务责任和状态仍以 Paperclip 为准。同来源事件先查已有映射，关联原根；不因在另一端出现同一需求而新建竞争根或重复执行。

## 关联链与缺项

最小链是：

`仓库／Issue／来源事件 → 原 Native root → 输入版本／SHA → 候选 → 原 PR／完整 head → CI → 通知`

| 环节／权威来源 | 映射身份与证据字段 | 缺项或未知结果处理 |
| --- | --- | --- |
| Issue／GitHub 来源事件 | 仓库 fullName、Issue 编号／URL、来源事件 ID；关联原 Native root | 来源或映射缺失记 unknown，先查原事件，不重复建根 |
| Native root／Paperclip | 原 Native UUID、项目／owner、责任人、授权范围；关联原 Issue 与输入版本 | 原根不能确认记 unknown，不凭标题推定或新建替代根 |
| 输入／Paperclip 证据引用 | 输入版本、文件 SHA、来源；关联原根及执行 run | 输入缺失记 unknown；未核验摘要记 NOT_RUN，不宣称已绑定 |
| 候选／产物与独立 QA | 产物路径、字节 SHA、执行 run、独评 run／范围／结论；关联输入和最终提交 SHA | 缺产物或评审结果记 unknown；未独评记 NOT_RUN，不推定内容通过 |
| 原 PR／head／GitHub | 原 PR、分支、完整 head、候选到提交的对应；关联原根和候选 SHA | 映射或当前读取缺失记 unknown；head 改变重绑独评，不以旧结论认证新候选 |
| CI／GitHub | 完整 head、检查／workflow run 身份、观察时间和结果；关联原 PR | 未触发或未读取记 NOT_RUN，结果不能确认记 unknown，不以旧 head 的通过替代 |
| 通知／飞书回执 | 原任务、正式 summary SHA、来源 run、通知 operation、受理与送达回执 | 缺送达回执记 unknown，未发送记 NOT_RUN；沿原 operation 对账，不盲目重发 |

每个箭头保存明确映射，不能凭标题、相近时间或口头总结推定。执行及独立 QA 的 run、候选字节 SHA、最终提交 SHA、原分支和授权范围映射进入内部证据。通知绑定原任务、正式 summary SHA 与来源 run，分别保存受理和实际送达结果。

缺少某环或结果不能确认时，该环记 unknown／NOT_RUN 并说明依据，不把整链写成成功。读取失败、未触发 CI 和未确认通知送达各自保留；其中一环失败不改写其他环的事实。

## 事实分层

1. 任务登记只证明目标及责任已保存。
2. 模型运行成功只证明该次运行取得结果，不自动证明内容正确。
3. 独立 QA 只认证其绑定的输入、范围和精确候选；内容或 head 变化后重绑。
4. PR／CI／合并分别记录真实身份和结果，旧 head 的检查不认证新 head。
5. 部署、业务验收、通知及资源收尾各有自己的回执，源码合并不能替代它们。

任务按已有效的持续授权推进，不为每次执行、QA 或普通 PR 环节重复生成决策卡。只有具体新增授权或改变结果的关键缺项才请求本人决定；澄清仅解决对应问题。暂停、同根继续、NEEDS_WORK 和 unknown 的具体处理统一遵守[恢复合同](task-lifecycle.md#中断与-unknown-对账)。

## 现役入口与旧入口隔离

现役配置合同为 ROLE、TEAM、CHIEF_FEISHU 开启；旧 DAILY、UNIFIED、EXECUTION 关闭。配置合同不是当前进程或连接健康证明；实际启用与动作效果必须另有运行回执。

本人使用已交付 [README 命令表](README.md#本人入口与项目选择)的 `/chief` 入口。旧 UNIFIED 关闭后，不承诺 GitHub 标签自动运行，不重开旧队列，不以旧 Docker／单 README 试点自述作为现役执行规则。旧身份、失败及预算留在内部历史证据，不重建或清零。

结果未知时沿原 operation 对账，不重复发送通知或新建替代 PR；同任务恢复入口见[生命周期](task-lifecycle.md)。公开正文不保存某一轮的临时状态、调用计数或宿主路径。
