# Super Agent 统一集成（受控试点）

GitHub Issue 和飞书是需求、补充与反馈的双入口；Paperclip 是唯一任务中台，统一保存任务身份、状态、责任人、人工决定和证据引用。两端消息应关联同一任务，重复事件不得重复执行。GitHub 仍是源码、PR 和 CI 结果的事实来源。

以下说明集成职责；实际能力以“证据状态”为准。

## 协作流程

1. **受理**：入口把需求和来源关联到 Paperclip，明确目标、文件范围、权限和验收条件。简短接收回执只表示收到意图，不代表已执行或完成。
2. **开发与独立评审**：开发者在授权范围内形成候选；另一位评审者独立核对实际候选、差异和证据。评审绑定候选 SHA 与任务范围，并提供授权范围摘要与范围标识（scopeId）的可核验映射；候选变化后重新评审，开发自检不代替独评。
3. **PR／CI**：通过 PR 提交源码或文档，记录同一候选的评审及适用 CI 结果，并回链 Paperclip。CI 通过只证明对应检查，不代表部署成功或跨平台支持。
4. **决策卡**：需要人工选择或授权时，列明问题、选项、影响、风险及具体候选。仅经核实的用户答复在该卡范围内生效；澄清、历史问题、工具输出和评审意见不自动成为执行授权。
5. **只读 Watchdog**：观察停滞、失败、缺失证据和状态不一致，提供告警与建议；不修改任务状态、不重试任务、不执行 Git 写操作、不重启服务、不合并或部署。

当前可见材料没有上述集成链路的验收回执，应按受控试点使用；无人值守生产就绪仍待验证。

## 失败恢复与人工决策

操作中断、超时或回执缺失时，结果保持“未知”，不能据此认定失败或未执行。恢复前先核对原操作记录、原 PR 及其候选 SHA／版本，确认是否已受理、实际执行到哪一步，以及远端结果是否与该版本一致。

核对完成前不得重复推送、新建替代 PR 或重复发消息；只读 Watchdog 只能提示核查，不能代为重试。缺少记录、身份冲突或无法确认结果时，保留原证据并暂停有副作用的操作，通过决策卡列明已知事实、未知项、原操作／PR／版本及可选处理方式，由人工决定；答复仅在明确授权范围内生效。

确认状态且取得所需授权后，仅继续原任务、更新原 PR；候选变化后重新独立评审并核验适用 CI。恢复流程、去重和决策卡的实际效果仍待验证，本文描述不构成验收通过。本任务始终不合并、不部署。

## 任务、版本与回执核对

恢复或继续修订前，逐项核对并记录证据引用：

1. **原任务 ID**：以 Paperclip 原任务 UUID 为准，同时核对展示编号 LEO-4、来源事件及授权范围；本任务 UUID 为 `fc7af371-dd33-484b-b567-60af5411ceae`。标题相同不能证明是同一任务。
2. **原 PR**：从原任务的记录核对仓库、PR 编号／链接、目标分支和开发分支，确认仍是原 PR。当前材料未提供可核验的 PR 身份，不猜测编号或新建替代 PR。
3. **输入版本**：记录本次需求修订标识、输入文档版本或哈希、授权范围标识及候选 SHA；与原操作使用的输入逐项比较。需求、输入或候选变化后，历史授权与评审不能自动覆盖新范围。
4. **最新 head 的 CI**：只读核对原 PR 当前 head SHA、检查名称、run／attempt 标识、状态和结果；确认回执中的被检验 SHA 对应当前 head，并注明合并测试提交与 head 的关系。旧 head 的成功、排队、取消或未知结果都不能记为当前候选通过。

历史回执保留其原任务、输入版本、候选 SHA、操作／run 标识、时间及来源。本次回执另记本轮身份与实际执行结果，并明确引用哪些历史证据、哪些已重新核验；同属一个任务或时间较近不足以互相替代。平台生成的快速接收回执只确认意图，不是本轮工作或验收证据。身份或版本缺失、冲突时标为“未知／待验证”，按上一节暂停有副作用的操作并交人工决策。

本轮仅形成文档候选，未查询远端原 PR 或最新 head 的 CI；上述核对流程及其集成效果仍待验证。
