# Chief 单图核验指南

本文说明在 RWB 中如何核对单图任务的任务 ID、输入版本、PR head 和 CI，确保核验结论对应同一项任务、同一份输入及同一次代码提交。

## 1. 核对任务 ID

1. 从 RWB 任务详情获取完整任务 ID。
2. 对照输入记录、生成结果和关联 PR 中标注的任务 ID，确认完全一致。
3. 不以任务标题、图片名称或相近的创建时间代替任务 ID。若记录缺少任务 ID 或存在冲突，先补齐或澄清关联关系，再继续核验。

## 2. 核对输入版本

1. 在任务记录中确认本次使用的输入版本，包括输入图片、需求文本及相关参数。
2. 对照执行记录和结果记录，确认它们引用同一输入版本；如有版本号、文件摘要或快照标识，应逐项比对。
3. 若输入在执行后发生变化，应区分旧版结果和新版输入，不得将旧版结果视为新版输入的验证结果。

## 3. 核对 PR head

1. 打开任务关联的 PR，记录当前 head 的完整 commit SHA。
2. 确认待核验的改动包含在该提交中，并与任务 ID 和输入版本对应。
3. 将核验记录中的提交 SHA 与当前 PR head 比较。若 PR 新增提交、发生 rebase 或被强制推送，原有核验结论需针对新 head 重新确认。

## 4. 核对 CI

1. 查看当前 PR head 对应的 CI 检查，确认检查关联的 commit SHA 与记录的 head 完全一致。
2. 按仓库要求核对所有必需检查，确认均已成功完成；运行中、排队、失败或取消的检查不能记为通过。
3. 对跳过或未触发的检查，确认其是否符合仓库规则；若必需检查未执行，应先解决触发或配置问题。
4. 不使用旧提交上的成功结果替代当前 head 的 CI 结果。

## 5. 记录核验结论

核验记录应包含以下信息，便于复查：

| 核验项 | 记录内容 |
| --- | --- |
| 任务 ID | RWB 中的完整任务 ID |
| 输入版本 | 版本号、快照标识或可追溯的文件摘要，以及对应需求和参数 |
| PR | PR 链接及当前 head 的完整 commit SHA |
| CI | 对应 head 的检查链接、必需检查结果及核验时间 |
| 结论 | 通过、未通过或待补充，并注明原因 |

仅当任务 ID 一致、输入版本可追溯、PR head 匹配且该 head 的所有必需 CI 检查通过时，才能记录核验通过。任一信息缺失或不一致时，应明确记录待处理项，完成修正后重新核验。

## 6. 关闭网页后找回原 Chief 对话和结果

1. 重新打开 RWB，使用原账号进入原工作区。通过保存的对话链接、浏览器历史记录或对话历史重新打开原 Chief 对话，不要新建任务代替原对话。
2. 使用已记录的完整任务 ID 定位原任务，并核对对话中的任务 ID、输入版本和原 PR 链接，确认找回的是同一项任务。
3. 在原对话和原 PR 中，使用已记录的 PR head 完整 commit SHA 查找对应的生成结果、核验记录及 CI 检查。继续沿用原 PR，不另建 PR。
4. 若原 PR 的当前 head 已变化，应将找回的结果标明为原 SHA 对应的历史结果，并按前文要求核验新 head；不得直接将历史结论用于当前 head。若无法找到原对话或对应结果，应记录缺失项，待恢复关联后再确认结论。
