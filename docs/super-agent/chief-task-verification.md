# Chief 任务验收说明

本说明用于 ResearchWorkbench（RWB）的任务验收。仅新增 `docs/super-agent/chief-task-verification.md`，交付止于可审查的 PR，不合并或部署。

## 核对步骤

1. **原生任务 ID**：从任务源记录读取原生任务 ID，与执行记录和 PR 说明逐项比对，确保指向同一任务。不得用任务标题、分支名或 PR 编号代替。
2. **输入版本**：记录本次执行实际使用的需求修订号及输入引用。本次需求修订号为 `revision: 1`；核对执行记录和 PR 说明中的版本一致，且内容对应本次需求。
3. **当前 PR head**：从 PR 当前状态读取完整 head commit SHA，并在验收记录中注明。确认 PR 差异仅包含本文件，内容符合本次需求。
4. **对应 CI**：查看关联到该完整 head SHA 的 CI 检查及运行详情，确认必需检查均已完成且通过。旧提交上的成功结果不能作为当前 head 的验收依据；缺失、排队中、运行中或失败的检查均不能记为通过。若未配置必需 CI，须明确记录，不得表述为 CI 已通过。

## 验收记录

在 PR 说明中记录原生任务 ID、输入版本、当前完整 head SHA，以及对应 CI 的链接和结论。任一信息缺失或不一致时，标明待核验项。PR head 更新后，重新核对 head 和对应 CI。

PR 应保持开放、可供审查，并提供上述核验信息；完成交付不代表已获批准或可以合并。

## 发布回执丢失时的核对

本次追加对应 `revision: 2`，继续使用同一个 RWB 原生任务和同一个 PR，仅修改本文件。发布回执丢失时，应先核对已有结果，不因缺少回执而直接重试发布：

1. 从原执行记录取得原操作 ID 和原分支，按原操作 ID 查询受管发布记录，确认记录关联同一原生任务、原分支和同一个 PR。
2. 读取当前 PR 的完整 head SHA，与受管发布记录中的提交 SHA 比对，并核对该 head 对应的 CI。原分支名称相同不足以证明提交一致；旧 head 的记录不能证明当前 head 已完成发布。
3. 在同一个 PR 中记录原操作 ID、原分支、当前完整 head SHA、受管发布记录链接及核对结论。若记录明确成功且各项一致，可据此补记结果；若记录缺失、状态未定或信息不一致，标明待核验，继续查询原操作，不得认定成功或盲目重复发布。

此处核对的是原操作的既有结果，不新增发布授权；本次交付仍止于开放、可审查的 PR，不合并或部署。
