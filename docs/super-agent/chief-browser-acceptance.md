# Chief 浏览器验收清单

本清单用于在 RWB 的浏览器验收与 PR 交付过程中，核对任务 ID、输入版本、当前 PR head 及对应 CI，确保验收证据属于同一次交付。

## 1. 核对任务 ID

- [ ] 打开任务详情，记录完整任务 ID 与任务链接。
- [ ] 确认任务要求与本次 PR 的交付范围一致。
- [ ] 核对 PR 描述中的任务 ID 与任务详情完全一致，不能仅凭标题相似判断。
- [ ] 若任务 ID 缺失或不一致，先修正关联信息，再继续验收。

## 2. 核对输入版本

- [ ] 在任务输入记录中确认本次执行采用的版本号，并记录对应输入内容或可追溯链接。
- [ ] 确认该版本是本次交付要求的版本；若有更新，核实更新是否已纳入本次执行。
- [ ] 对照该版本的要求检查 PR 内容，避免使用旧版本要求验收新提交。
- [ ] 若输入版本无法确认，暂不判定验收通过。

## 3. 核对当前 PR head

- [ ] 打开目标 PR，确认仓库、PR 编号、目标分支与任务交付目标一致。
- [ ] 从 PR 当前最新提交中复制完整 head commit SHA，并记录核对时间。
- [ ] 确认变更文件只有 `docs/super-agent/chief-browser-acceptance.md`。
- [ ] 检查该文件的最终内容，确认是中文清单，覆盖任务 ID、输入版本、当前 PR head 和对应 CI 的核对步骤。
- [ ] 提交验收结论前刷新 PR，再次确认 head SHA 未变化；如有变化，重新核对变更与 CI。

## 4. 核对对应 CI

- [ ] 从当前 PR 的检查区域打开 CI 详情，记录检查名称、运行链接、状态及其关联的 commit SHA。
- [ ] 确认 CI 对应当前记录的 PR head SHA，不能将历史提交上的成功结果作为当前 head 的证据。
- [ ] 若 CI 检查的是平台生成的合并提交，确认该运行关联的 PR head SHA 与当前 head 一致，并记录合并提交 SHA。
- [ ] 确认所有必需检查均已完成并通过；排队中、运行中、失败、取消或需人工处理的检查均不能记为通过。
- [ ] 对跳过或未触发的检查，核实仓库规则并记录原因，不将其直接等同于成功。
- [ ] 若 CI 重跑，核对最新有效运行及其关联提交，避免引用已被替代的结果。

## 5. PR 交付记录

- [ ] 将以下记录填写在目标 PR 描述或验收说明中，方便复核。
- [ ] 确认所有链接可访问，任务、输入版本、head SHA 与 CI 证据能够相互对应。
- [ ] 仅在上述核对完成且必需 CI 通过后，记录验收通过；否则注明未通过的原因。

| 核对项 | 记录 |
| --- | --- |
| 任务 ID 与链接 | 待填写 |
| 输入版本与依据链接 | 待填写 |
| PR 链接 | 待填写 |
| 当前 PR head 完整 SHA | 待填写 |
| CI 名称、运行链接与结果 | 待填写 |
| CI 关联的 head SHA | 待填写 |
| 合并提交 SHA（如适用） | 待填写 |
| 核对时间 | 待填写，注明时区 |
| 验收结论与未通过原因 | 待填写 |

## 6. 关闭网页后重新打开原 Chief 对话

- [ ] 重新打开原 Chief 对话，用此前记录的完整任务 ID 打开任务详情，确认仍是原任务，并核对当前输入版本及补充要求。
- [ ] 沿用原分支和原 PR，核对 PR 链接、编号及源分支，不另建任务、分支或 PR。
- [ ] 刷新原 PR，重新复制当前 head 的完整 SHA，并记录本次核对时间；不要直接沿用关闭网页前的 head 或验收结论。
- [ ] 在原 Chief 对话中定位原任务 ID 对应的最新结果，核对其输入版本、PR 链接和 head SHA 是否与当前记录一致；若缺失或不一致，先补齐或更新结果，再继续验收。
- [ ] 按第 4 节重新核对当前 head 对应的最新有效 CI；历史 head 的成功结果不能证明当前 head 已通过。
- [ ] 若 head 已变化，重新检查文件变更和最终内容，确认只修改本文件且保留前文、仅追加本节，再核对对应 CI。
- [ ] 在原 PR 的交付记录中更新任务 ID、输入版本、当前 head、CI 链接、核对时间和结论；提交结论前再次刷新确认 head 未变化，仅在全部核对完成且必需 CI 通过后确认最新结果验收通过。
