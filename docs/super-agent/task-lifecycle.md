# Super Agent 任务生命周期

本页说明同一任务从登记、输入版本、Chief 计划与按需委派，到产物、独立 QA、原 PR／CI、总结及恢复的合同。Paperclip 是唯一任务、运行和会话控制面；阶段名是逻辑交接名称，不是新的 Native 状态机，也不要求与界面状态一一对应。

本人入口、执行环境、岗位、原根预算和 RWB 权限以[接入说明](README.md)为准；三端责任见[统一集成](unified-integration.md)，GitHub 来源准入见[GitHub 入口](github-intake.md)。仓库交付遵守[根规则](../../AGENTS.md)和[Agent 工作流](../AGENT_WORKFLOW.md)。文档不授予工具或远端写权限。

## 同任务推进

| 逻辑阶段 | 动作及必须保留的证据 | 后续条件 |
| --- | --- | --- |
| 登记 | 核对真实本人、来源消息／事件、仓库和项目；查已有映射，关联原 Native root 与责任人 | 来源和范围可核对；重复事件不另建根或并行执行 |
| 固定输入 | 保存原目标、输入版本与 SHA、允许文件、成果、验收、交付终点及授权来源 | 输入足以执行，缺项具体列出；澄清不扩大授权 |
| Chief 计划与按需委派 | 计划绑定输入版本；按依赖选择必要岗位，跨职责共享对象指定唯一执行者，登记原执行 key、子任务和 run | 不强制跑遍所有岗位；预算和原计划可续接 |
| 产物与独立 QA | 读取原件后制作候选，登记实际文件 SHA、完整变更和实际验证；独立会话核验精确候选与输入 | 自查不代替 QA；NOT_RUN 和发现保留；有修改则复核新候选 |
| 候选与原 PR／CI | 获准集成人将产物落入允许路径，形成提交并绑定原分支、原 PR、完整 head；按完整变更集验证并独评 | 字节候选 SHA 与 Git commit SHA 分开；集成改变内容后另审最终候选 |
| 总结与恢复 | 分别总结产物、QA、源码／PR、CI、合并、部署、通知和资源收尾 | 已完成事实有对应回执；缺项、失败和 unknown 不被摘要覆盖 |

仅产物任务止于候选。仅 PR 任务止于原 PR，不合并、不部署；其他任务按当前可信项目和任务许可执行，不把旧试点终点写成永久禁令。具体项目开发授权、交付终点和任务绑定的 DevOps 发布能力见[接入说明](README.md#rwb-交付边界)。

## 补充、暂停与继续

在本人已配对的飞书单聊中，项目参数放在动词之前。完整命令表见[本人入口](README.md#本人入口与项目选择)。

| 命令 | 同根语义 |
| --- | --- |
| `/chief --project rwb add <任务号> <补充要求>` | 先持久保存 pending 输入，暂停后续派发；在途 run 明确终态后应用新输入版本，不改写其原输入绑定 |
| `/chief --project rwb pause <任务号>` | 暂停后续派发，保留在途运行、原 operation 和累计预算；未知结果不能改标取消 |
| `/chief --project rwb continue <任务号>` | 继续原根；同版本未完成计划复用，新输入按最新要求重建计划；unknown 先对账 |

可省略任务号使用所选任务。普通目标沿既有持续授权执行，不反复增加决策卡或计划确认；只有改变结果的关键缺项、新增授权或不可解决的阻塞才提出精确问题。本人选择 plan-first 时按该一次计划后暂停合同处理。

原根预算覆盖 Chief、执行、QA、返修及总结，补充、暂停、继续、重启、新会话与输入改版不清零。当前原根可信额度和响应上限见[预算合同](README.md#原根预算返修与恢复)。已完成根的独立新目标才用 followup；失败修正或 unknown 不能借新根重置预算。

## QA 返修及候选变化

QA 成功运行后给出 NEEDS_WORK，是质量返修而非传输失败。发现返回同一个执行子任务及执行 key；保留旧失败、旧产物、旧 QA 和原累计耗用。修复后交独立会话重验新候选，最多两轮质量返修；不能用 `retry-now` 代替返修，也不能另建根或替代 PR。

产物预审、最终集成候选独评及发布分别绑定 SHA。输入、范围、head、基线或 CI 证据变化时，重新核对评审适用性；旧 PASS 不自动认证新候选。最终评审须记录精确 head、完整差异、验证回执、输入版本及范围映射。

获准修订已发布内容时沿原任务、原分支和原 PR 推进；不沿用旧“只支持首次创建 PR”的结论。实际修订、基线刷新、验证与发布遵守当前受管入口和许可，不能从本文推定某个动作已执行或可跳门。

## CI 等待与交付

| 观察 | 必须记录及处理 |
| --- | --- |
| 排队／运行 | workflow、run／attempt、观察时间、完整 head 与实际 checkout；不是 PASS |
| 通过 | 仅认证同候选的对应检查；同时核对独评、分支保护、讨论和所有适用门 |
| 失败／取消／超时 | 保留原结果，沿同任务修复；新候选重新绑定检查与独评 |
| 未触发／无法读取 | NOT_RUN 或 unknown，附具体原因和下一责任人；不能用旧绿色或配置存在替代 |
| head／基线／CI 变化 | 保留原证据归属，重新核对候选、检查和评审，不从旧结论直接放行 |

检查路由覆盖正文与导航的完整 changed set；Project Constraints 和 Research Web Checks 是通用仓库门，不能冒充原生平台验收。适用本平台 CI、其他平台交接及 Actions 额度按[工作流](../AGENT_WORKFLOW.md)和[额度治理](../actions-budget.md)处理。

受管 `delivery --status` **可能执行合并**，不是只读状态查询；`--defer-cleanup` 只延迟清理，不移除合并行为。只观察时必须使用获准只读通道，不能以查询名义越过仅 PR 或仅产物终点。

## 中断与 unknown 对账

恢复先读取原输入、计划、产物和真实回执，区分未执行、尝试、失败、unknown 与已成功。缺本地回执不证明动作未发生；摘要声称成功也不能补写 PASS。

- 模型／外部动作 unknown：沿原 operation、dispatch、run 和来源事件对账，不换 ID 重发，不重复推送、建 PR 或发通知。
- 候选写出后中断：核对实际字节、SHA、输入版本和登记身份，匹配则复用；部分输出保留原失败。
- PR 创建或更新响应丢失：只读核对原仓库、分支、PR 与完整 head，确认后接续原操作；身份不明保持 unknown。
- setup 或连接失败：记录实际失败阶段、是否已启动、脱敏错误与责任人，不伪造模型成功。连接问题交 Network Engineer。
- 暂停或重启后：不删锁、许可或账本制造可重试状态，不重置预算，不恢复无权操作。

## 最小交接字段

内部证据至少记录：来源及观察时间、仓库／Issue／事件、原 Native root 与执行子任务／key、责任人、原 operation／dispatch／run、输入版本与 SHA、授权／scope 映射、允许路径与终点；实际文件及 SHA、完整 changed set、原分支／PR／完整 head、基线；独评者／会话／run、候选与结论、发现及返修历史；实际命令、退出码、可审阅脱敏输出与摘要；CI workflow／run／attempt／预期及实际 checkout；NOT_RUN／失败／unknown 原因、恢复点、下一责任人；通知回执及资源收尾。

任务登记、模型成功、QA、源码合并、部署和通知均是独立事实。公开正文只维护稳定合同和必要历史；临时计数、宿主路径、候选验收流水放入任务内部证据。
