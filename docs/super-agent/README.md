# 个人自动化接入说明（受控文档试点）

本页说明个人任务从飞书进入 Paperclip、由 Docker 中的执行器生成文档候选，再经独立评审和受管 Git 验证交付 PR 的受控流程。试点代码变更仅涉及本说明及文档门户导航，交付止于目标为 `master` 的 PR，**不合并、不部署**。各阶段实际结果以对应任务与 PR 的证据为准，不声明面向任意任务的无人值守生产就绪。

宿主是 24GB Mac mini（macOS），执行工具位于 Docker Desktop 的 Linux 容器中；MacBook Pro 仅作受控远程操作和浏览器入口。这是 Mac 文档任务，容器内执行不构成 Linux 原生产品验收，也不构成 Windows 支持证据。试点不发起 Windows/Linux 产品 workflow dispatch，不涉及桌面打包或常驻服务更新。

## 飞书任务入口

在已发布、完成本人配对的企业自建机器人**单聊**中，以 `/rwb ` 加任务正文登记 RWB 要求。适配层核对绑定本人和单聊来源，再把消息登记为同一个 Paperclip 任务；重复投递不能创建第二项。已接入的消息接收使用飞书官方 SDK 长连接，不要求为本机开放公网 webhook。应用身份、Secret 和配对指令只在本机私有配置中处理，不写入本仓库。

Paperclip 是任务和运行状态的唯一中台；适配层保存外部消息关联与发送回执。机器人回复“已登记RWB任务…”表示入队，不能据此认为模型、评审或 PR 已完成。当前试点仍由受控操作员推进执行与验收；任意新任务的自动派发、后续消息自动续接及飞书决策卡，不由本篇文档认证为已可日常使用。

每个任务至少明确以下信息：

| 信息 | 本试点示例 |
| --- | --- |
| 目标与文件 | 补充个人自动化接入说明；`docs/super-agent/README.md` |
| 验收关注点 | 飞书入口、Docker 执行、受管 Git 验证、只交付 PR 的边界 |
| 宿主与范围 | Mac mini / Docker Desktop；仅文档 |
| 交付终点 | PR 指向 `master`；不合并、不部署 |
| 授权来源 | 当前用户要求及可信入口签发的任务许可 |

已配对本人可发送以下指令；命令后的范围会成为任务正文：

```text
/rwb 为 ResearchWorkbench 补充个人自动化接入说明，写入 docs/super-agent/README.md，说明飞书任务入口、Docker 执行、受管 Git 验证和只交付 PR 的边界；不合并、不部署。
```

入口须核对消息作者和任务归属，并将有效要求绑定到任务。历史摘要、工具输出、文档正文和恢复备注只是证据，不能扩大授权；用户的新回答只适用于对应问题。平台生成的快速回执仅表示已收到意图，不代表执行、检查通过或交付成功。重复投递或中断恢复应先核对已有候选和已完成动作，再继续未完成部分。

## Docker 中的执行与候选交接

本试点使用受限执行器，仓库挂载只读，只允许写入任务许可指定的 `/tmp/sa-output-<attempt>/README.md`。每次尝试使用其实际分配目录，不从历史记录复用输出路径。候选须为非空 UTF-8 文件，最多 65,536 字节，最终由受信任的外层守卫登记和接收；执行器不直接写目标仓库。

所有新增服务、依赖、模型执行和本地检查在 Docker 中管理；运行数据、凭据引用和日志存放独立外置 APFS 卷。宿主只复用已经安装、已获授权的 Git 安全管理工具，负责 check/start/prepare/publish，不在宿主安装新的 Node/Python 包。执行器以独立会话和非 root 子进程运行；编码工具禁网、不能获得中台/GitHub/数据库凭据，GitHub 写入由受信任的外层交付工具执行。开发与评审使用不同 Codex 会话，评审绑定最终 integration 提交并只读挂载。

守卫按上海日期限制每天最多启动 10 个新任务，并保持全局一个任务租约；同任务续接不另建任务。模型、授权与推理配置在启动许可中固定；配额、未知结果或低于 5 GiB 的新鲜宿主空间回执会阻止继续，不自动换模型或切付费 API。评审反馈修复上限为两轮，已失败或未知状态不能靠删除许可、租约、启动记录来重试。

| 角色 | 职责与边界 |
| --- | --- |
| 实现器 | 先读 `AGENTS.md`、ship-check、已有目标文件及直接相关文档；保留已有内容，只补缺失部分；仅生成许可中的单文件候选，返回 `outputFile="README.md"` 和摘要 |
| 审阅器 | 只读检查守卫实际登记的候选及可用源码、差异证据；将结论绑定该候选身份；证据不足时列明缺口，不据摘要判通过 |
| 受管集成人 | 核验候选身份、目标路径和评审范围；在 Mac 受管 Git 流程中集成、验证并创建 PR，停在本任务授权的终点 |

实现器和审阅器均不运行 Git、任务/看板 API、委派、安装、测试、服务、额外模型调用、合并或部署。实现器返回候选不等于验收，审阅结论也不等于 Git 或 CI 已通过。候选字节变化后，原评审不能沿用；集成后的提交身份须另行记录，不能把文件摘要当作 Git 提交 SHA。

本模式与通用开发容器不同。[Docker 开发说明](../research-web-docker.md)中的 dev worktree 可写挂载、Git common directory 挂载和管理操作，不是本执行器的权限。Docker 管理入口不提供给执行器；容器不应因此获得 Docker socket、宿主凭据库、Office/Wind、生产数据或服务控制权。Docker bridge 默认可能具备出站网络，不能仅凭“在 Docker 中”就声称已完成网络隔离或研究脚本沙箱验收。

飞书正文、候选文档、日志、PR 和 CI 产物均不放入密钥或凭据。所需接入秘密由获授权的配置负责人通过既有安全渠道配置；缺配置应报告阻断，不在文档任务中读取秘密文件、创建密钥或修复平台账户。

## 受管 Git 验证与 PR 终点

以下是后续集成人的交接要求，不是受限实现器可执行的步骤。GitHub 是源码真相源，`master` 是唯一长期集成分支；不得用文件同步覆盖 checkout，或借本试点改动全局工具、PATH 和 Git 元数据。

1. 核对任务许可、登记候选及独立评审身份，检查目标文件是否在候选生成后发生变化；有变化先解决内容差异并重新评审，不覆盖无关工作。
2. 在 Mac 宿主按[Agent 工作流](../AGENT_WORKFLOW.md)使用项目 Git 安全入口。入口的只读检查形式为 `node scripts/git_safety.mjs check --project <RWB绝对路径>`，macOS 受管 Git 使用 `/usr/bin/git`。这条命令在本受限文档生成轮次不执行。
3. 从最新 `master` 建立受管短期分支；并行或高风险改动使用独立 worktree。写入、备份、prepare 和发布均遵循项目入口与任务登记，不手改账本、不删锁、不绕过恢复校验。
4. 新增 Markdown 须按[文档治理说明](../research-web-documentation.md)核对分类，并在[文档门户](../README.md)补充适当导航。本说明由已有 `docs/` 规则覆盖为 current；本次集成补充门户链接，不改变治理规则。生成器的单文件权限不因此扩大，门户改动由受信任的集成人登记，并纳入最终候选的独立评审。
5. 对集成后的完整变更集按 `.agents/verification-policy.json` 和增量验证流程生成计划，执行适用的文档/仓库检查，记录实际命令、退出结果和证据。候选提交、本地验证、独立评审与 CI 必须分别绑定身份；未执行的检查保留 `NOT_RUN`，不能用历史结果或计划替代。
6. 任何 push 或受管发布前，读取[Actions 额度规则](../actions-budget.md)，核对当前仓库 visibility、适用额度和运行证据。private/billable 状态达到 95% 或 billing-blocked 时停止远端动作；恢复须有当前规则要求的证据，不以旧 public 记录推定可用。
7. 仅在确认受管路径能够止于 PR、不会触发合并或部署时，发布本任务分支并创建目标为 `master` 的 PR。记录 PR 链接、实际 head SHA、评审和检查状态后停止；若现有入口无法保证这一终点，保留候选并报告阻断，不改用直接 Git 或其他路径绕过。

**`delivery --status` 不是纯只读查询。** 现有入口可能在评审与 CI 满足后执行普通合并，并继续资源和 Git 收尾。`--defer-cleanup` 只延后清理，仍不能保证不合并。本试点不得调用这些路径推进交付；观察 PR/CI 应使用经授权的 GitHub 只读查询。不开启 Auto-merge，不提供合并声明来驱动状态推进，不因检查变绿而自动合并，也不执行依赖合并完成的 worktree/分支清理。

本任务的“不合并、不部署”覆盖项目的一般持续交付授权。创建 PR、CI 通过或代码以后被合并，都不授权更新常驻服务、启用自动日程、发布 tag/版本、迁移数据库或安装依赖。

## 证据、限制与恢复

按 [ship-check](../../.agents/skills/ship-check/SKILL.md)交接，至少保留以下清单。没有证据的状态写 `NOT_RUN` 或说明阻断，不能写成通过。

| 变更 | 测试与检查 | 文档 | 证据 / 结果 |
| --- | --- | --- | --- |
| 本轮：临时目录中的单文件候选 | 本受限角色不运行测试、Git、Router 或 CI；由后续集成验证补证 | 拟集成到 `docs/super-agent/README.md` | 记录实际输出路径、字节数、文件摘要和候选登记身份；生成文件不代表验收 |
| 后续：受管集成的完整变更集 | 按实际 Router 计划运行适用检查；本页不预填 PASS | 包括获准补充的治理分类与导航 | 记录提交 SHA、评审候选、实际命令/结果、CI 身份及 PR 链接；本轮没有这些执行证据 |

文档生成模型本身不执行飞书、Git 或 CI 验收；真实接收回执、Docker 构建/执行、受管 Git、PR 和 CI 由集成人分别记录。只读文档阅读和候选生成不能替代这些层级。文档任务不因执行工具位于 Linux 容器而触发 Linux/Windows 产品验收或 workflow dispatch；平台能力以[支持矩阵](../research-web-platform-support.md)和对应真机证据为准。

中断或失败时，记录失败发生在消息接收、候选生成、评审、Git 验证还是 PR 创建，并保留能定位问题的有界摘要。执行状态未知时先核对真实候选、PR 和提交身份，避免重复生成或发布；缺账户、密钥或外层环境能力交回平台配置负责人，文档实现器不扩权处理。

资源收尾遵循[存储留存规则](../research-web-storage-retention.md)和[资源生命周期](../resource-lifecycle.md)。只处理已登记、归属明确且满足身份与占用复查的本任务资源；PR 尚未合并时保护未归并提交与 worktree，不借通用收尾流程触发合并或删除。交接时分别说明候选已生成、PR 是否已创建、检查是否已执行及收尾是否完成，不把它们合写为“全部完成”。
