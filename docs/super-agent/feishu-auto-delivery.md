# 交付证据核对与登记关联完整性

本文用于核对任务、输入、候选、PR、CI及结果通知的证据归属，不是自动部署说明。历史文件名保留，不代表自动交付权限或调度器已开启。

本人入口、角色与预算见[接入说明](README.md)，同根推进及授权见[任务生命周期](task-lifecycle.md)，三端权威见[责任与证据关联](unified-integration.md)，来源准入与原PR续接见[GitHub入口](github-intake.md)。本文只维护登记与交付证据合同；回执丢失和原操作恢复见[结果核对与恢复](chief-daily-result-recovery.md)。

## 一、任务登记与来源去重

- 记录真实任务名称、目标、需求来源及来源事件、负责人、登记日期、当前状态、预期成果与可观察验收条件。缺项标明待补充及跟进人，不以空项表示通过。
- 以仓库、Issue、来源事件与原Native任务映射查重；相同需求保留主记录和关联记录，不仅凭标题或时间合并。重复ID、错误引用先查原始记录，更正时保留原因与来源。
- 从任务详情读取完整Native任务ID，与输入、执行、结果、候选及PR说明逐项比对；任务标题、PR号、分支名、图片名称不能替代身份。
- 仅在显式plan-first或实际适用的决策门下，记录待确认／已确认／不采纳、确认人、时间、依据、分歧及跟进人，并核对确认后的范围、优先级和负责人。普通有效持续授权不新增“所有候选先批准”门；澄清不等于批准。
- 任务对多个PR时逐项写用途；PR对多个任务时列明每个任务映射。核对仓库、标题、内容、目标分支及状态，分别记录待评审、修改中、已合并或已关闭。未创建写“未创建”，不需PR写“不适用”及原因。
- 按需要盘点遗漏、重复、错误关联、状态差异、当前head及下一负责人；记录观察日期、时区、核对人和未解决事项，下次优先复查。此盘点不新增每日调度器、每日任务硬上限或竞争任务库。

## 二、固定输入与附件来源

记录任务ID及链接、`inputRevision`、允许文件、交付终点和适用授权／审批门；有绑定时另记`scopeId`、`baseCommit`、`expectedHead`。将实际需求文本、参数、附件与该输入版本对应，检查补充要求是否已纳入。缺失或冲突保留差异、来源链接和待核对状态，不猜测补值。

图片或附件须有来源、原始文件或快照标识、字节摘要、需求参数及输入版本；执行和生成结果引用同一输入。输入变化后，旧结果只属于旧输入。保存原件，转换保留编码、BOM、换行、数据类型、结构与可表达元数据，不能表达的差异逐项交接。未提供真实图像、OCR或工具执行时只能陈述核对方法，不宣称图像生成、OCR或截图验收通过。

## 三、候选与当前PR身份

| 身份层 | 核对要求 |
| --- | --- |
| 输入基线 | `baseCommit`／`expectedHead`及需求版本属于执行输入，不冒充新产出 |
| 产物字节 | 文件路径、字节SHA256、生成来源及独评范围，不能当作Git提交SHA |
| 产出Git候选 | 完整提交SHA、完整changed set及字节到提交的映射 |
| 当前PR head | 现场读取仓库、原PR、源分支、目标分支及完整head，记录观察时间 |

新候选不必等于旧基线；登记候选须与当前PR head建立明确对应，不能用分支名、提交标题或短SHA证明相等。确认最终内容与实际允许路径相符。新增提交、rebase或其他head变化后，旧独评和CI只认证旧候选；新字节或新head另作精确审查，不延伸旧PASS。提交结论前刷新PR确认head未变化，变化则重新核对。

## 四、CI归属及验收层级

逐项保存必需workflow、job、run ID、attempt、触发事件、运行链接、预期候选、实际checkout完整SHA、状态和结论。检查PR关联及运行详情，不能凭绿色图标、同分支或相近时间确认归属。

直接检查候选时核实实际checkout与适用候选；若平台检查合成merge提交，分别记录合成merge SHA、关联PR及关联head，并核实其对应当前候选。实际checkout不必机械等于PR head；关联不明保持待核对。旧提交成功不能认证当前head。

按仓库规则核对最新有效运行和具体attempt，保留先前失败与被替代运行。排队、运行中、失败、取消、待人工处理、缺失均不能记通过；跳过或未触发须说明规则与原因，未运行记NOT_RUN，归属或结果无法确定记unknown。未配置必需CI也须明确写明，不能写CI已通过。

通用仓库检查、原生平台验收、生产验收分别记录。Ubuntu／Linux Docker不能替代macOS原生或Windows真机；各平台由对应设备承担原生证据。PR合并不等于安装、业务或生产验收。完整源码Router、平台CI及生产操作以实际候选和回执为准，文档检查不替代它们。

## 五、历史回执与正式结果

| 记录 | 可证明范围 |
| --- | --- |
| 快速ACK、收到、开始处理 | 受理意图，不是成果、QA、授权或合并 |
| 同任务旧输入 | 历史结果，不能证明新需求 |
| 同输入旧字节／候选／head | 只认证原版本，新版本另核 |
| 同候选旧attempt | 保留原归属，核最新适用运行，不掩盖失败 |
| 身份一致但缺CI、独评或适用审批 | 缺项待验证，不写完成 |
| 当前身份及证据可追溯 | 只汇报实际覆盖层级，部署与通知另证 |

消息日期、排列顺序、历史问题或工具输出都不是新批准。正式summary与来源run、原任务和字节摘要绑定；快速ACK、旧摘要与本次正式通知是不同事实。通知受理与实际送达分开，缺送达回执为unknown；沿原operation对账，不因丢回执重发。

## 六、稳定通知表达合同

默认中文，先写真实任务标题和内容，编号仅作辅助；标题缺失明确写缺失，不编造目标。说明可信当前阶段、结果或原因及下一步，不把历史QA预览写成当前阶段。

可信调用用量单列，不从调用数、token或产物数推算完成率。显示持久化通知日期及Asia/Shanghai时区，不把Git提交或摘要称作版本；只有权威发布元数据确有SemVer才使用发布版本。默认正文不展开Native UUID、QA run UUID、SHA256或内部错误码，完整技术证据保留原任务档案。

表达调整不改变QA结论、预算、blocked／unknown或部署验收。保留原outbox身份、去重关系与技术summary，不重放已发送通知、不合成入站事件；通知样式不证明真实送达。

## 七、文件格式与能力分层

Document Specialist负责文本／数据交换、标记文档、LaTeX/BibTeX及Office/PDF文件的结构与转换；Research/PM负责来源与业务结论，Designer负责视觉规格，独立QA验证正式文件。应用代码、部署配置与数据库行为按对象交技术负责人，扩展名不扩大权限。

交接输入输出路径、实际格式、编码、原件与摘要、生成工具、转换损失和NOT_RUN。语法/schema、字段及记录数、内容口径、公式写入、实际重算与缓存值、LaTeX编译及引用、Office/PDF渲染、OCR各层分别取证。Markdown写成不证明Office重算、编译、渲染、OCR或真人连接可用；Skill分配、工具声明、安装及版本查询也不证明已连接或业务验收。可提取文本PDF优先直接解析，扫描件先核本地OCR版本、模型及后端；外传另守授权。连接问题交Network Engineer，不复制凭据或改认证。

## 八、可复查交付记录

空项不表示通过，仅填实际证据，不放秘密。

| 核对项 | 应记录内容 |
| --- | --- |
| 任务与登记 | 真实标题、完整ID、来源／事件／主记录、负责人、日期、状态、成果与验收 |
| 输入与授权 | inputRevision、scopeId（如有）、需求／参数／附件摘要、允许路径、交付终点、适用决定依据 |
| 基线与候选 | baseCommit／expectedHead、文件字节SHA、完整Git候选、changed set及独评范围／结论 |
| PR | 原仓库／分支／PR／目标分支／当前完整head，多对多用途映射及观察时间 |
| CI | 每项workflow／job／run／attempt／event／实际checkout／关联head／合成merge／链接／状态／结论 |
| 历史 | 旧输入、旧候选、旧attempt和原operation／发布回执关联 |
| 分层结果 | 通用检查、平台、生产、通知受理／送达、资源收尾分别说明 |
| 缺项与下一步 | 核对人、时间和时区、差异、NOT_RUN／unknown原因及下一负责人 |

只有身份与证据可核实时才陈述对应层级通过；任何缺项先交后续受管流程核验。此记录不替代原账本、不授予重跑、合并或部署权限。
