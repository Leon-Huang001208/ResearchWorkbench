# 报告生产配置页精简设计

## 目标

将报告生产配置页从“展示全部生成链路诊断”调整为“帮助用户完成本期配置”。默认界面只回答用户当前最关心的问题：报告是否可直接生成；只有存在阻断项或用户主动查看时，才呈现详细诊断和编辑入口。

## 已确认的交互方向

- 正常状态采用方案 A“安静默认”：展示就绪结论、本期报告日期、证据窗口与简洁的覆盖统计。
- 异常状态采用方案 B“待办优先”：仅展示阻止生成的项目，每一项均提供一个直接进入对应配置位置的操作。
- 用户可通过“查看检查详情”按需展开完整检查；详情保留现有 Prompt、Evidence 与输出资产诊断能力。

## 信息架构

### 配置页顶部

保留报告名称、报告日期、证据窗口及“高级配置”入口。健康状态使用下列两种文案：

- 正常：`可直接生成`，附 `23 个占位符已配置 · 19 个正文段落可检索生成` 一类的汇总。
- 异常：`有 N 项待处理`，附阻断项数量和最优先动作提示。

配置页不再在左栏默认展示“Prompt 覆盖”“Evidence 覆盖”“输出资产”的逐项列表。

### 生成检查卡

将 `#template-project-check-details` 的默认呈现切换为状态驱动：

1. **可生成**：卡片收起，仅在摘要中展示 `全部检查通过`，以及映射数、可写作段落数和一个“查看检查详情”按钮/summary。
2. **不可生成**：卡片自动展开，渲染最多三个按优先级排列的阻断待办。每项包括清晰的人类可读问题、影响说明和现有 `focus-placeholder` / `open-advanced` 操作入口。
3. **详情模式**：用户展开后，再展示当前完整三组预检（Prompt 覆盖、Evidence 覆盖、输出资产）与 Evidence 抽样；它不再是默认视图。

### 校验规则与数据

不改变后端 `CompiledReportPlan`、`validationChecks`、`placeholderReadiness` 或生成拦截判断。前端只新增一个面向 UI 的状态模型，从现有 `readiness` 中计算：

- `state`: `ready` 或 `blocked`；
- `summary`: 占位符映射数、evidence 写作段落数、待处理数量；
- `actions`: 仅取未通过检查与未就绪占位符，去重、排序后最多显示三项；
- `details`: 复用现有 `buildPreflightReviewGroups()` 的完整诊断分组。

排序规则：先缺少 Word 映射/Prompt/检索 Query 等会阻断生成的项，再缺少 Excel、表格和图表来源，最后展示只影响提示质量的 warning。若无法定位到配置项，保留“打开高级配置”安全回退入口。

## 组件与边界

- `app/web/static/js/templates.js`
  - 新建紧凑检查状态构建函数，集中负责从 `readiness` 构造摘要与待办，避免模板渲染函数自行判定业务状态。
  - 调整 `renderTemplateValidationPreview()`：始终渲染紧凑摘要，仅在异常自动展开；详情在用户打开时渲染或复用已有三组内容。
  - 复用既有 action 属性和 click handler，不改变编辑器导航协议。
- `app/web/templates/index.html`
  - 将“生成预检”静态占位内容替换为摘要、待办和按需详情三个明确容器；使用可访问的按钮文本和 `aria` 描述。
- `app/web/static/style.css`
  - 为 ready / blocked / expanded 三种状态提供局部样式；正常态高度应接近 100–140px，异常态不依赖长列表滚动。
- `tests/unit/test_report_template_workbench_frontend.py`
  - 覆盖新的静态 DOM 约定、状态构建、正常态不默认渲染 Evidence 抽样、异常态保留现有定位操作与详情入口。

## 错误处理与可访问性

- Readiness 数据缺失或非预期时显示 `检查状态暂不可用` 和“重新检查”/“打开高级配置”回退入口，不把页面渲染为误导性的可生成。
- 待办操作缺失 target 时安全回退到高级配置，而非生成无效按钮。
- 状态更新应同步更新 `aria-expanded` 与可见区域；键盘可以展开详情并激活待办动作。

## 验收标准

1. 当所有检查通过时，左栏不出现 Prompt、Evidence 或输出资产逐项列表；用户一眼能看到可生成结论、日期、证据窗口和覆盖统计。
2. 当存在阻断项时，左栏自动显示至多三项可执行待办，且点击能打开正确的占位符/高级配置。
3. 用户仍能通过明确入口查看完整预检详情及 Evidence 抽样。
4. 报告生成前的拦截逻辑及现有后端计划数据不发生改变。
5. 现有前端单元测试和新增状态覆盖测试通过。
