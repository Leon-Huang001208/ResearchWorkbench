# AlphaFoundry 系统配置中心设计

## 目标

为 AlphaFoundry 桌面工作台新增“系统配置”页面，集中管理迁移到新机器后必须补齐的外部服务配置。用户在页面保存配置后，后端持久化配置并立即刷新支持热更新的运行参数；无法安全热更新的数据库连接明确标记为“重启后生效”。

首版覆盖：

- 大模型 Provider、Token 与任务模型路由
- 知秋账号池与账号轮询参数
- iFinD 账号、后端类型与 HTTP 地址
- 数据库连接地址
- 日志和 LLM 并发、重试等高级运行参数

首版不覆盖云端同步、多人权限、系统钥匙串集成或任意环境变量编辑器。

## 方案选择

采用“统一配置服务 + 本地配置文件”方案。前端只通过配置 API 读取和更新配置；后端统一负责校验、脱敏、持久化、热更新和审计日志。

不采用数据库作为唯一配置源，因为数据库连接本身不能可靠地依赖数据库配置，且会增加迁移和故障恢复难度。不允许前端直接编辑原始文件，避免格式损坏、密钥泄露和运行状态不同步。

## 页面结构

左侧工作区导航新增“系统配置”入口，对应独立的 `section-config` 页面。页面包含：

1. 配置概览：显示整体就绪度，以及大模型、知秋、iFinD、数据库四类配置的状态。
2. 大模型：支持多个 Provider，字段包括名称、协议、Base URL、API Token；支持任务到 Provider 和模型的路由配置。
3. 知秋：支持账号行的新增、删除和编辑，并配置轮询策略、最大重试次数、重试间隔、租约超时和连续失败阈值。
4. iFinD：配置用户名、密码、后端类型和 HTTP Base URL。
5. 数据库：配置连接地址，并始终展示其重启生效语义。
6. 高级配置：折叠展示日志级别、日志目录、LLM 并发数、重试次数和分块参数。

每个分区独立保存，避免修改一个区域时意外覆盖其他区域。保存结果逐项显示“已生效”“重启后生效”或字段级错误。

## 后端架构

新增配置业务服务，路由保持轻量：

- `ConfigurationService` 负责读取当前配置、构造脱敏视图、校验更新、原子持久化和刷新运行状态。
- 配置 API 提供读取配置与按分区更新配置的端点。
- API 请求和响应使用明确的 Pydantic 模型，禁止接受任意环境变量名。
- `.env` 继续承载通用运行配置；知秋账号使用 JSON 编码的环境值，避免旧逗号、冒号格式无法表达复杂密码的问题。
- 写入使用同目录临时文件和原子替换；写入失败时保留原文件。

配置服务更新进程环境，并刷新 `core.settings.config.settings` 中可安全更新的字段。模型 Provider、知秋、iFinD 和高级参数在保存后对后续新建客户端或任务立即生效。数据库 URL 会持久化，但不替换活动 SQLAlchemy 连接池，响应返回 `restart_required=true`。

## API 与数据流

### 读取

`GET /api/config`

返回分类配置、就绪状态和生效状态。所有敏感字段仅返回：

- `configured`: 是否已经配置
- `masked_value`: 可选掩码，例如末尾四位

绝不返回完整 Token、密码或包含密码的数据库 URL。

### 更新

`PUT /api/config/{section}`

`section` 仅允许 `llm`、`zhiqiu`、`ifind`、`database`、`advanced`。请求仅包含该分区字段。敏感字段采用三态语义：

- 省略或空字符串：保留已有值
- 提供新值：替换已有值
- `clear_secret=true` 或对应清除标记：显式删除

响应包含更新后的脱敏分区、`applied`、`restart_required` 和消息。校验失败返回 422；持久化或刷新失败返回 500，日志记录异常但不记录秘密值。

### 连接验证

`POST /api/config/{section}/test`

首版为大模型、知秋和 iFinD 提供验证入口。验证使用尚未保存的表单值与已保存秘密合并后的临时配置；验证失败不修改持久配置。数据库首版只做 URL 结构校验，不主动切换或创建新连接池。

## 安全规则

- API 响应、异常文本和日志均不包含完整秘密。
- 前端密码框默认为空，使用“已配置”状态表达已有秘密。
- `.env` 和本地秘密配置必须保持在 Git 忽略范围内；配置文件权限在支持的平台上设置为仅当前用户可读写。
- 不把秘密写入浏览器 Local Storage、URL、DOM 数据属性或前端日志。
- 删除账号或清除秘密必须由显式用户操作触发。
- 现有知秋明文 YAML 账号仅作为兼容读取来源；保存配置后改用环境中的结构化账号数据，页面不回显旧密码。

## 错误处理与日志

- 所有文件读取、解析、校验、写入和运行时刷新均有异常处理。
- 配置文件格式错误时，读取接口返回可理解的配置错误，不覆盖原文件。
- 保存前完成全部校验，避免部分字段落盘。
- 原子写入失败时记录配置分区和错误类型，不记录提交内容。
- 成功保存记录分区、生效模式和被修改的非敏感字段名。
- 日志继续使用 `core.observability`，写入项目 `logs/` 目录。

## 测试与验证

后端测试覆盖：

- 敏感字段脱敏且不回传原值
- 分区请求模型和数值边界校验
- 空秘密保留、替换和显式清除
- `.env` 原子更新且保留无关配置和注释
- 知秋结构化账号的特殊字符处理
- 热更新字段与数据库重启标记
- 持久化失败和非法分区的错误响应

前端静态回归和浏览器验证覆盖：

- 导航入口和配置页面可访问
- 各配置分区能加载脱敏状态
- 新增、删除知秋账号和 Provider 行
- 保存成功、字段错误及重启提示
- 页面和日志不出现已保存秘密
- 深色、浅色主题下的主要布局和窄窗口适配

## 迁移与兼容性

现有环境变量仍可继续使用。配置页首次打开时读取当前环境和 `.env`，将其映射为脱敏状态。用户保存后写回相同的受支持变量，因此命令行和桌面启动方式保持兼容。

旧 `ZQ_ACCOUNTS=user:pass,...` 继续支持读取；新保存使用 JSON 结构，账号管理器优先读取 JSON，再回退旧格式和现有 YAML。数据库变更在下一次桌面后端启动时生效。

## 完成标准

- 用户可以从左侧导航进入系统配置页面。
- 五个配置分区可以读取、编辑和持久化。
- 保存后后端返回明确的实时生效或重启生效状态。
- 敏感字段从不明文回显或进入日志。
- 新机器无需手工编辑文件即可完成首版依赖配置。
- API、服务和前端测试通过，并完成浏览器交互验证和相关文档同步。
