# 系统配置编辑器重构设计

## 背景

现有系统配置弹窗将集合型数据渲染为密集的类表格控件。输入、显示、复制和删除动作混杂，视觉层级不足；部分字段被环境配置锁定时，用户不能区分“不可编辑”和“当前未配置”，导致新增、修改和保存的预期落空。

本次重构覆盖大模型服务、知丘账号池、iFinD 账号池和联网搜索 API Key 池。目标是让用户能在同一套清晰、可预测的交互中创建、编辑、测试并保存配置。

## 范围与信息架构

保留卡片入口与单个配置弹窗。一个弹窗只处理一个配置主题：

- 大模型服务使用“服务与密钥”和“任务路由”页签，降低单屏密度。
- 知丘、iFinD、联网搜索分别使用“账户或 Key 集合 + 运行参数”两段式布局。
- 数据库与高级配置不调整业务字段，仅复用新的底部操作和锁定状态表达。

不变更后端配置接口、持久化格式或环境变量优先级。

## 交互设计

### 集合编辑

集合不再依赖仅有列头的静态表格。桌面端每一行仍紧凑对齐，但字段本身保留明确标签；窄屏改为垂直字段组。

“添加服务 / 账号 / Key / 路由”会在对应集合的顶部插入一条编辑态记录，自动聚焦第一个字段，并标记为未保存。空集合使用操作导向的空状态和主操作按钮。

既有记录直接编辑。移除操作使用清晰的“移除”文案和危险样式，并在操作后的保存前保留可撤销空间；不在单击时立即持久化。

### 密钥处理

已有密钥仅显示“已配置”，不回显秘密值。用户可以通过“替换密钥”输入新值，或显式选择“清空密钥”；只有输入非空替换值或选择清空时才会提交密钥变更。不会提供无作用的“显示 / 复制”组合。

### 保存、测试与反馈

Footer 固定在弹窗底部，顺序为：状态提示、取消、测试当前配置、保存更改。

- 表单有未保存改动时显示未保存状态；关闭时要求确认。
- 测试请求发送当前表单值但不保存；成功、失败和需要重启均在 footer 就地展示。
- 保存按钮仅在表单有改动、配置已加载且没有进行中的请求时可操作。
- 前端继续使用现有 400 / 403 / 409 / 422 / 500 错误映射，并在 422 时显示字段校验信息。

### 环境锁定

仅由启动环境变量覆盖的具体字段禁用。被禁用字段旁显示“由启动配置管理”的原因和对应变量；集合其他可编辑字段继续可用。整个集合仅在其数据源整体被环境变量接管时锁定，且新增按钮与空状态都应说明原因。

## 组件边界

在 `app/web/static/js/configuration.js` 中将集合行的新增、删除、秘密值状态和脏状态保持在现有渲染函数中；抽取共享的集合操作状态辅助函数，避免四个分区各自判断可编辑性。

在 `app/web/static/configuration.css` 中以配置弹窗根节点范围限定样式。移除相互覆盖的旧式“表格 / 彩色卡片”规则，使用统一的行容器、字段标签、空状态、footer 状态和响应式断点。

后端 API 不变；现有 `PUT /api/config/{section}` 和 `POST /api/config/{section}/test` 继续负责校验、保存和未保存配置的测试。

## 错误处理与日志

前端保留网络和结构化 API 错误处理：请求失败不清空表单，失败消息必须可见且不会伪造“已保存”状态。后端不引入新的日志路径；现有配置路由在持久化失败时继续写入项目日志。

## 验收标准

1. 四个集合型配置页面均能新增、编辑、移除行，并且保存后重新加载显示一致。
2. “测试当前配置”使用尚未保存的值，且不改变后端已保存的快照。
3. 配置秘密值不能被回显或复制；替换与清空状态能正确提交。
4. 环境锁定只影响相应字段或集合，并向用户说明原因。
5. 未保存改动在保存、关闭、测试和请求失败场景下有准确状态反馈。
6. 1440px 桌面宽度下不出现拥挤、截断或不可点击的操作；720px 以下字段按垂直布局显示。
7. 现有前端单元测试、配置 API 测试与静态检查通过。

## 自检

本文档未包含占位项。范围限定于现有配置 UI 与交互；后端契约不变。环境锁定、密钥安全、测试与保存的关系均明确且不冲突。
