# 系统配置弹窗信息布局重设计

## 决策

本轮采用“紧凑专业工具”方向，并按内容类型使用两种统一版式：

- 账号与 Key 池使用紧凑数据表；
- 高级运行参数使用设置导航与参数清单；
- iFinD 等空账号分区使用单行空状态与直接新增入口。

深色主题、既有模块色、保存、测试连接、环境锁定、秘密值脱敏和现有 API 均保持不变。此次仅改变信息层级、DOM 展示与 CSS 布局，不改变配置语义。

## 目标

消除现有弹窗的三个视觉问题：

1. 账号池将每条记录渲染为一张大卡，滚动长度过长、可扫读性差。
2. 空账号分区保留表头与大片内容留白，用户无法快速判断下一步。
3. 高级配置将全部参数平铺为同等尺寸的大输入框，重复的锁定说明掩盖了参数间的关系。

完成后，用户应在一次扫视中找到当前配置数量/状态、可编辑值、受管理值以及保存或测试操作。

## 适用结构

### 1. 账号与 Key 池：紧凑数据表

适用于知丘账号、iFinD 账号和联网搜索 Key。

- 小节标题左侧为名称，右侧为 `新增账号` 或 `新增 Key`；不使用大色块标题。
- 非空时使用统一表头和一条记录一行的表格。名称、用户名/Key、秘密状态和操作严格对齐。
- 已保存的秘密只显示掩码或“已配置”；不因重设计回填秘密。
- 删除降级为小型文字或图标操作，危险色仅在悬停、聚焦或确认语义中使用，不再绘制整颗红色大按钮。
- 空时隐藏表头，显示一行虚线空状态：说明“尚未添加账号/Key”，并保留临近的新增入口。
- 每一记录的编辑、删除、环境锁定与 payload 过滤逻辑不变；窄屏时切换为带字段标签的堆叠行，不能裁切重要操作。

### 2. 连接与搜索设置：低噪声字段组

适用于 iFinD 后端类型/Base URL、搜索 Provider、轮询策略、配额与超时。

- 不再为单个选择控件制造大面积容器；字段按照控制类型和长度组成两列或三列网格。
- URL、长文本、密码和密钥保持跨整行；选择项和短数值使用更小的单元。
- 当账号池为空时，连接设置在空状态之后直接出现，不能预留“账号表格”的高度。
- 小节标题只承担分组与简要说明，不使用粗色竖线、渐变背景或连续嵌套边框。

### 3. 高级配置：设置导航与参数清单

高级配置不再把每个锁定参数都作为一张表单卡。

- 左侧为稳定分类导航：`运行与日志`、`LLM 处理`、`文本分块`；小窗口改为顶部横向分段导航。
- 右侧为按组展示的参数清单，每行包含名称、最多一行说明、当前值与锁定状态。
- 由启动环境管理的字段维持禁用和原有 `aria-describedby` 说明，但重复提示压缩为行级弱说明；footer 保留总览式锁定提示。
- 可编辑字段继续使用原有 input/select；锁定字段可以采用只读值显示，但必须不改变表单序列化、保存 payload 与可访问状态。
- 不增加新设置项，也不改变参数的默认值、范围或后端校验。

## 通用弹窗规则

- 弹窗宽度随内容受限于合理的桌面最大宽度，正文滚动、页脚固定。
- 标题区保持模块图标、标题、简短副标题和关闭按钮；色彩仅用于图标和不超过 3px 的顶部标识线。
- `保存更改`是唯一高强调按钮；`测试连接`是描边次级按钮；`取消`是文字按钮。
- 支持连接测试的分区显示“测试连接不会保存当前更改”；不支持测试的分区不显示该文案或测试按钮。
- 页面、表面、弱表面不超过三层背景；使用 1px 低对比边框、8px 间距基准和清晰的主/次/辅助三级文字颜色。
- 卡片、弹窗与表单的键盘焦点、Escape 关闭、滚动、200% 缩放及窄屏可用性必须保持。

## 实现边界

- 主要改动限定在 `app/web/static/configuration.css` 和 `app/web/static/js/configuration.js`；只有在现有弹窗容器缺少必要的语义钩子时才调整 `app/web/templates/index.html`。
- 复用现有 `config-dynamic-row`、`config-field-grid`、环境锁定与空状态生命周期；允许重命名展示类，但不能删除被测试或事件绑定依赖的数据属性。
- 不改变 `ConfigurationService`、配置 API、桌面端启动参数、连接测试流程或秘密值处理。
- 禁止新增图标库、第三方 UI 库、网络请求与全局配色系统。

## 验收标准

1. 五条账号记录在桌面端以一张表容器呈现，不再出现五张等高大卡；操作列对齐且窄屏可用。
2. 空 iFinD/Key 池只显示新增入口和一行说明，不显示无数据表头或大面积留白。
3. 高级配置在分类和参数值间形成明确层级，锁定状态不再通过每行重复的大段说明抢占视觉空间。
4. 保存、测试、取消与锁定提示的视觉权重一致；保存与测试真实行为不变。
5. 账号/Key 新增、删除至空、远端刷新、环境锁定、秘密值不回填与 payload 过滤的现有测试继续通过。
6. 通过静态前端测试、JavaScript 语法检查，以及本地浏览器中已配置账号池、空 iFinD 池与高级配置三个场景的视觉检查。
