# AlphaFoundry 桌面端快速启动设计

## 目标

消除桌面端重复启动后端造成的 `8765` 端口冲突，并确保启动页不会因单次健康请求悬挂而无限等待。

## 设计

- 桌面端采用单实例插件；再次打开应用时聚焦已有主窗口，不再创建第二套后端。
- 启动 sidecar 前对 `127.0.0.1:8765/health` 做带超时的 HTTP 探测。已有健康服务时直接复用，只有服务不存在或不健康时才创建子进程。
- 启动页的每次健康检查使用 `AbortController` 设置短超时，并保留总计 90 次重试；耗尽后显示可重试状态。
- 桌面壳只保存并终止自己成功创建的 sidecar，复用的外部服务不归当前实例管理。

## 错误处理与日志

- 探测连接、写入或读取失败均视为未就绪，并记录可诊断日志后继续正常启动 sidecar。
- 单实例回调聚焦窗口失败时记录警告，不使应用崩溃。
- sidecar 创建失败继续由启动页展示连接失败状态。

## 验证

- Rust 单元测试覆盖健康响应识别和真实本地 TCP 健康探测。
- 桌面脚手架测试覆盖单实例注册、启动前健康探测和前端请求超时。
- 运行 Rust、Python 桌面专项测试，并执行格式检查。
