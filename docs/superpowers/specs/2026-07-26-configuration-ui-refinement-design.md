# 系统配置页面布局精修设计

## 目标

在不改变配置分区、保存接口、连接测试机制或编辑路径的前提下，精修系统配置首页及全部六个配置弹窗的视觉层级、排版和操作语义。页面应保持深色控制台气质，但不再呈现为大面积仪表盘或彩色卡片堆叠。

用户打开页面后应能快速分辨：已完成的配置、还需要处理的配置，以及进入任一分区的明确入口；不需要先理解“健康总览”“首次配置”和“本次已验证”等内部概念。

## 范围与非目标

### 本轮范围

- 系统配置首页的标题区、概览、配置卡片网格、状态筛选和响应式排版。
- 六个配置弹窗的标题区、分组、空状态、字段网格、底部操作栏和锁定提示的视觉一致性。
- 将首页“重新检测”改名为“刷新状态”，并用可见帮助文本说明其行为。
- 保留现有配置卡片、模态框、保存、测试连接、锁定字段、卡片键盘操作和所有 API 调用。

### 非目标

- 不重构配置分区或配置数据结构。
- 不移除连接测试，也不把刷新状态改为隐式连接测试。
- 不改变环境变量锁定、秘密值脱敏、保存权限或后端验证。
- 不引入新的图标库、设计系统依赖、接口或桌面端 sidecar 行为。

## 首页设计

### 容器与标题

页面主内容限制为适合宽屏阅读的最大宽度，并在可用区域内居中；不再把模块卡片拉满超宽桌面。标题区域为一行：左侧保留“控制台 / 系统配置”和说明，右侧放低强调的 `刷新状态`。

`刷新状态`只重新读取当前配置快照、数据库运行就绪信息，并清除当前会话中短暂的连接测试显示；它不发起外部连接测试，也不保存配置。按钮旁的提示文本或 tooltip 必须明确这一点。卡片与弹窗内的 `测试连接` 继续是唯一执行实际验证的入口。

### 概览

将现有健康总览和首次配置横幅合并为一张紧凑的进度概览卡：

- 主指标：`已完成 X / 6 项`，附一条进度条。
- 次指标：`Y 项待配置`，只有存在待办时使用暖色强调。
- 状态入口：展示连接异常数量或“暂无异常”，可展开查看当前会话验证状态。

不再单独展示“首次配置”大横幅、五个步骤徽章或四个等权数字格。下一项未完成配置仍从已有 readiness 数据推导，但只在概览的辅助文字或状态筛选中表达，不能抢占主要页面空间。

### 配置模块卡片

保留六个模块和卡片点击打开编辑弹窗的交互。桌面端使用三列紧凑网格，中等宽度两列，窄屏单列；不再在宽屏强制排列五张超宽卡片。

每张卡片的固定结构为：

1. 顶行：小尺寸模块识别图标与文字状态。
2. 中部：模块名称和一行摘要。
3. 底部：分隔线后的文本操作 `管理配置 ›` 或 `去配置 ›`。

图标从视觉主体缩小为识别符。模块主题色只用于图标底色、操作文字和必要状态，不能使用大面积辉光。成功、待配置、待验证和异常均同时使用文字、图标和颜色，不只依赖颜色。

## 配置弹窗设计

### 通用框架

弹窗采用一致的中等宽度、12px 圆角和短标题区。模块色仅用于顶部 4px 色线、标题图标及该模块的局部主操作；正文和页脚使用中性深色背景。

关闭按钮放在标题区右侧。正文可滚动，底部操作栏保持固定；`保存更改`是唯一高强调主按钮，`测试连接`为描边次级按钮，`取消`为低强调文本按钮。

连接测试说明必须显示为：“连接测试会使用当前填写但尚未保存的设置；不会写入配置。”仅在该分区支持测试时展示。

### 表单、分组与空状态

- 账号/Key 池为空时，不显示没有数据的表头；以带有新增入口和简短解释的空状态替代。
- 选择类字段使用两列网格；短数字参数使用三列网格；URL、名称、密钥、长说明等保持单列。
- 每一组使用标题、简短辅助说明和细分隔线，避免当前的粗色竖线、重复边框和过多空白。
- 高级配置保留更保守的单列或两列布局，防止参数含义被压缩。
- 环境锁定字段、动态集合锁和弹窗 footer 锁定说明继续保留，只改为低干扰中性样式，且维持现有 `aria-describedby` 关联。

## 视觉规范

- 背景层级限制为页面底色、表面和弱强调表面三层；统一 1px 低对比边框与 8–12px 圆角。
- 标题、正文、辅助文字采用明确的三级字色；不再以模糊的灰色承载可操作信息。
- 紫色为全局主操作色；分区色只做局部识别，成功为绿、待办为暖黄、异常为红，避免将颜色滥用到整张卡片。
- 采用 8px 间距基准：标题区 24px、概览/模块区 24px、卡片内边距 16px、字段网格间距 12–16px。
- 维持键盘焦点样式、模态焦点管理、窄屏单列布局以及 200% 缩放下的操作可见性。

## 实现边界

- 主要修改 `app/web/templates/index.html`、`app/web/static/configuration.css` 和 `app/web/static/js/configuration.js` 中的展示文本、DOM 结构、状态渲染和类名。
- 不改变 `ConfigurationService`、配置 API 模型、持久化语义或环境锁定规则。
- 现有 `connectionStateBySection` 继续保存本会话测试状态；`刷新状态`调用原有加载流程并重置它。
- 现有卡片操作、模态框字段回填、payload 过滤及 secret 不回填约束必须不受影响。

## 验收与测试

1. 首页不再出现独立“首次配置”大横幅或四个等权统计格；概览、待办和连接状态可在一个紧凑区块理解。
2. 页面标题区出现 `刷新状态`；帮助文案明确它不测试连接、不保存配置。
3. 六张配置卡在桌面三列、中宽两列、窄屏单列下不溢出，且状态与操作均可辨识。
4. 所有配置卡仍可通过点击和键盘打开对应弹窗。
5. 空账号/Key 池展示新增入口与解释，非空时保留现有编辑、删除和锁定行为。
6. 弹窗底部保存、测试和取消操作清晰分级；测试说明与实际行为一致。
7. 已有秘密值不回填、环境锁定提示、payload 过滤、后端拒绝路径和连接状态刷新测试继续通过。
8. 通过静态前端测试、JavaScript 语法检查，并在可用本地桌面/浏览器环境中验证首页、至少一个空 Key 池弹窗、一个已配置模块弹窗、窄屏布局及键盘操作。
