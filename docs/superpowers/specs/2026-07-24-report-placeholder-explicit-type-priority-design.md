# 报告占位符显式类型优先设计

**日期：** 2026-07-24

## 问题

报告模板工作台中，已配置段落 `mode` 的占位符切换为短字段、固定文案、表格或图表后，会在类型归一化时被旧 `mode` 再次判定为 `paragraph`。用户确认切换后，界面仍显示“正文段落”。

## 目标

让用户明确保存或选择的 `type` 成为占位符输出形态的权威值，同时保留段落专属配置，以便用户以后切回正文段落时恢复原有写作设置。

## 范围

- 调整 `app/web/static/js/templates.js` 的占位符类型归一化优先级。
- 为该优先级规则增加前端静态回归测试。
- 同步 Web 工作台模块文档与变更日志。

不包含：

- 删除历史段落 `mode`、Prompt、检索或数据模板。
- 修改后端 API、报告项目 YAML schema 或模板自动推断规则。
- 扩展中文占位符名称的表格/图表推断。

## 设计

### 类型优先级

1. 若调用方传入有效的显式 `type`，归一化函数返回该规范类型。
2. 若没有显式 `type`，且历史 mapping 保留了有效的段落 `mode`，返回 `paragraph`，保持旧配置兼容。
3. 若两者都没有，沿用现有名称/section 推断逻辑。

有效类型保持现有集合：`paragraph`、`field`、`static_text`、`table`、`chart`。

### 数据保留

切换到非段落类型时，只更新 mapping 的 `type`。不删除 `mode` 或其关联内容。后续切回 `paragraph` 时，既有段落配置仍会被渲染和使用。

### 保存与渲染

既有草稿收集、保存和重新渲染流程不变。修复后，它们在接收到 `mapping.type` 时不会再由旧 `mode` 覆盖该值。

## 回归测试

在 `tests/unit/test_report_template_workbench_frontend.py` 中验证：

- 归一化逻辑先检查有效的显式 `type`。
- 遗留段落 `mode` 仍作为没有显式类型时的兼容回退。
- 类型卡片切换和草稿收集均调用同一归一化路径，显式类型不会回退为 `paragraph`。

浏览器验证应复现原始路径：选择有段落 `mode` 的占位符，切换到短字段并确认，然后验证选中状态和隐藏 `type` 字段均为 `field`。

## 错误处理与兼容性

- 未知 `type` 不应被视为显式有效类型，继续走已有兼容推断。
- 历史仅含 `mode`、没有 `type` 的配置继续被识别为段落。
- 本次不引入新接口、持久化字段或迁移。

## 验收标准

1. 具有 `mode: evidence_ai` 等历史段落配置的占位符，切换并确认任意非段落类型后，选中卡片和草稿 `type` 保持新类型。
2. 保存、切换其他占位符再切回后，新类型仍保持。
3. 切回正文段落时，原段落写作设置仍存在。
4. 静态回归测试与浏览器交互验证通过。
