# 系统配置控制台设计

## 目标

把“配置入口集合”升级为可读、可操作、可诊断的系统配置控制台，同时不改变既有配置 API、秘密值脱敏和环境变量锁定边界。

## 方案

页面顶部新增系统健康总览：展示已就绪、待补齐、会话内已验证和异常数量，并提供“继续配置”入口。首次配置引导根据 `llm`、`database`、`zhiqiu`、`ifind`、`web_search` 的现有就绪状态计算步骤；点击后打开第一个待配置项的既有编辑模态框。

每张配置卡片保留完整卡片点击和键盘操作，并将其页脚动作文字改为“去配置”或“管理配置”。连接测试继续只在既有模态框中执行；前端仅在本次页面会话中记录其测试结果，成功显示“连接已验证”，失败显示“连接异常”。刷新或重新加载后该状态被清空，避免将瞬态测试冒充持久运行健康度。

环境变量锁定说明收起为简要提示并带“查看受管配置”控制；详细字段仍由现有锁定逻辑渲染，不泄露秘密值。卡片保持现有模态框架构及卡片轻微亮化交互，遵循项目的可访问性和紧凑操作台规范。

## 边界与验证

不新增后端存储、健康检查 API 或数据库迁移；不改变 `/api/config/{section}/test` 的测试语义。新增静态回归断言以锁定总览、引导和会话级连接状态的关键标记，并用 Node 语法检查保障静态导入模块可解析。浏览器验证覆盖：待配置项的继续配置、卡片主动作、模态框测试成功/失败后的状态更新、刷新后的状态复位。
