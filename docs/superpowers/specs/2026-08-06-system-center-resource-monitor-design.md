# 系统中心与资源监控 UI 设计

日期：2026-08-06
状态：已获用户认可，待实施

## 目标

将“系统监控”和“系统配置”收拢为单一的“系统”入口，降低侧栏重复入口与页面跳转成本；改善资源监控页的状态表达、异常密度和历史筛选体验。

## 范围

### 包含

- 侧栏由“系统监控”和“系统配置”收拢为一个“系统”入口。
- 系统入口内提供“资源与异常”“系统配置”两个页内标签；默认打开“资源与异常”。
- 去除正常状态下的右上角 `ok` 徽标。
- 将待处理异常改为紧凑行式列表，操作按钮保持在行尾。
- 将异常历史的原生状态、严重度下拉框改为深色触发按钮与浮层单选列表。

### 不包含

- 不改变资源采集、告警阈值、告警持久化、配置 API 或配置字段。
- 不引入 React、Tailwind、组件库或新的前端框架。
- 不把“资源与异常”和“系统配置”拼成一个无限长页面。

## 信息架构

```text
侧栏：系统
  ├─ 页内标签：资源与异常（默认）
  │   ├─ 容量摘要
  │   ├─ 待处理异常
  │   ├─ 活跃归因、趋势图、受限进程树
  │   └─ 异常历史与筛选
  └─ 页内标签：系统配置
      └─ 现有配置工作台
```

实现上保持现有 `section-resource-monitor`、配置表单字段、数据属性与 API 调用不变；新增的系统入口只负责在两个既有工作区之间切换，以避免干扰配置模块当前的独立初始化、保存和错误处理逻辑。

## 组件与交互

### 系统入口与标签

- 侧栏显示一个“系统”按钮，点击进入系统中心。
- 进入系统中心时，默认激活“资源与异常”。
- “系统配置”标签切换到现有配置工作台；从配置内部发起的配置导航仍进入此标签。
- 资源监控仅在“资源与异常”可见时轮询；切到系统配置或其他入口时停止轮询。

### 状态表达

| 状态 | 页面表现 | 可交互性 |
| --- | --- | --- |
| 正常且无待处理异常 | 不显示右上角状态徽标 | 正常 |
| 有待处理异常 | 显示“n 个待处理异常”提醒，可定位待处理列表 | 正常 |
| 采样暂不可用 | 显示明确的“采样暂不可用，保留上一帧数据”提醒 | 保留历史、暂停误导性新值 |
| 监控部分降级 | 仅显示有影响的字段或异常说明；平台不支持的磁盘 I/O 继续显示“当前平台不支持” | 正常 |

### 异常列表

- 每条异常采用紧凑行：严重度色条、标题、摘要、时间/范围、确认与解决操作。
- 不在常态下显示大面积灰色卡片；保留严重度色条和键盘焦点可见样式。
- 未恢复异常保持置顶；其计数是系统入口的唯一常态提醒。

### 历史筛选器

- 每个筛选器是带标签、当前值和箭头的按钮，例如“状态　全部⌄”。
- 点击后打开深色浮层，选项为单选列表并以勾选标识当前值。
- 状态：全部、未确认、已确认、已解决；严重度：全部、严重、警告、信息。
- 点击外部、按 `Escape` 或选中一个值后关闭浮层；选中后立即刷新历史列表。
- 使用按钮、菜单语义和焦点管理，不使用原生 `select` 外观。

## 兼容与错误处理

- 资源监控公开接口、事件接口和配置接口均不改变。
- 保留现有资源监控的安全 DOM 写入方式；新增筛选器不使用不受控 HTML 注入。
- 配置加载、保存、令牌获取和锁定字段逻辑保持原状。
- 正常状态不渲染无意义的成功徽标；采样失败仍保留上一次有效数据和重试信息。

## 验收与验证

- 静态测试覆盖：单一“系统”侧栏入口、两个页内标签、默认标签、无 `ok` 正常徽标、浮层筛选器的 ARIA/键盘契约。
- JavaScript 检查、资源监控与配置相关单元测试通过。
- 浏览器验证：标签切换会正确启动/停止采样；正常、待处理异常、采样失败、筛选器展开与选择四种状态均可见且可操作。
- 不修改用户现有未提交的配置业务逻辑或文档内容；提交仅包含此 UI 改动及其测试/报告。
