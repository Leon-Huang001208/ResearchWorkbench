# 暂停知丘数据源抓取设计

## 目标

暂停知丘研报、知丘公众号和知丘会议纪要三个数据源的定时抓取及深度历史回补，同时保持其他数据源、已抓取数据、入库队列和断点状态不变。

## 设计

- 在三个知丘 `SourceSpec` 中显式设置 `enabled=False`，由现有注册表统一阻止调度任务和启动补漏任务加载。
- 不删除知丘连接器、凭证、历史数据、PDF、抓取状态或队列中已经产生的任务。
- 修改配置后向当前调度器进程发送正常终止信号，由现有 watchdog 自动拉起新进程并重新读取注册表；其他已启用数据源会自动恢复调度。
- 恢复抓取时只需移除三个源的停用标记并再次平滑重载调度器。

## 错误处理与日志

- 重载前记录当前调度器 PID；若 PID 不存在，则仅保存停用配置，不尝试终止未知进程。
- 重载后检查新 PID、心跳和调度状态；若 watchdog 未拉起调度器，报告实际状态，不启动额外的重复调度器。
- 保留现有 `logs/` 调度日志，使用其中的启动、停机及任务清单记录作为运行证据。

## 验证

- 验证注册表中三个知丘源均为 `enabled=False`，其他来源状态不变。
- 验证新调度器进程存活，且任务清单不含 `zhiqiu_reports`、`zhiqiu_wechat`、`zhiqiu_transcript` 或对应的 ZQ 深度回补任务。
- 检查重载后的日志，确认没有新的知丘抓取启动记录。
