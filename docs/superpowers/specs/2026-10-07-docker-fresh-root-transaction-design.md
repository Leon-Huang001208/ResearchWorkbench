# Fresh Docker root transaction repair

macOS Web, original automatic-port/dual-runtime goal; base75b9da6c6. This fixes a
reproduced installation/first-start transaction gap, not a new architecture.

## Evidence

Public Docker no-start installation in a new private HOME built its image, then
failed runtime_stop_current_required. Product root, all Native ledgers/endpoints
and accepted Docker manifest were absent. The shared checkout already had an
owned valid Native venv, so NativeRuntime.status entered the subprocess bridge
and classified daily default8088/3081 listeners as potential current-root writers.
The no-venv branch had different missing-root behavior. Merged master does not
change these four source files. Daily listeners must not be stopped or adopted.

## Required contract

Final no-start selection is under a real lifecycle lease. A strictly absent
product root, pinned safe parent, absent Native records/endpoints and no known
containers can establish only current missing-root selection safety. Accept
image/mode without making product data, PID/endpoints or controls; no allocation
or control-origin mutation. Do not serialize this observation or derive it from
mode/manifest/venv presence. Readonly status alone is not writable authority.

Subsequent actual Docker start independently acquires its lease and checks the
same absence. It creates the real private root through existing stdlib/private
filesystem helpers, pins its inode/parent and retains creation authority only in
that lifecycle transaction. Reuse the already-tested Native creation-capability
principles, not its dependency/runtime implementation. Known container or any
existing root/Native record, malformed record, symlink/reparse, substitution,
lease loss or newly observed possible same-root writer refuses as before.

A live healthy existing-mode reuse must never gain fresh authority. Allocation
authority expires before spawning; exact attempt-only RAM recovery may retain
the proof needed to restore controls only after all attempted owned children or
containers are confirmed gone. Preserve original error/rollback diagnostics and
token/extra fields; no general unsafe-root retry, fake records or permissions fix.
No new Native prerequisite for Docker; no global changes or secret reads.

No-start proof ends with that call; a later start must acquire its own facts.
Do not create the product root in no-start then lose the proof. Shared default
ports are not evidence of an instance belonging to a provably newly created root.
This is a narrow exception justified by root creation, not an unknown-writer bypass.

## Verification

Genuine RED valid owned venv+new private HOME+real foreign default-product listeners;
no-start succeeds without root/controls/endpoints. Standard Docker start obtains
its own actual creation proof. Keep existing-root/no-ledger/unknown-same-data,
substitution/forged-lease/unknown-container/failed-start cleanup negative cases.
Existing verification policy/planner/receipt and logging/error handling only;
no new probes/framework/dependencies. Main alone owns actual Docker builds/services.
Tests, module docs and task report accompany code; independent spec/quality/security
review before merging into managed feature and before physical retest.
