# 专业 Agent 可靠协作 MVP

## 边界与入口

FinGPT 现有研究页面新增显式“专业协作”模式。用户确认保守准入额度后才提交；普通研究和 Claw 沿原流程。维护者发布 Orchestrator、Industry、Quant、Review 配置，模型继承当前会话冻结路由。角色不提供额外的数据或工具权限，不启动第二套执行循环。

Host 保存业务 DAG、不可变角色与 Skill 版本、预算和验收；DSH 主 Agent 规划调度，原生 continuable 子会话执行，原生 settlement 唤醒父 Agent。每次补充研究创建新的子会话，明确引用相关成果。实际 Skill 读取证据由原生子历史核验，提示词要求不能替代读取证明。

## 合同与状态

`GET /api/research/specialists` 发现四个受审角色；现有消息接口增加 `research_mode=specialist` 与 `specialist_budget`。预算要求明确确认、正整数 Token 准入额度和原生模型请求次数，并发不超过2、时限不超过1800秒、自动计划修订不超过2轮。改图、审查返工共享修订限制；单次调用以实际 Agent/turn/step 去重。

`GET /api/research/sessions/{sid}/specialist` 只观察归属当前账号的状态；`POST .../specialist/resume` 必须明确确认。续跑创建关联的新运行，保留历史成果、已消耗和未知预留，不自动补足原预算。只有可证明未提交的尝试或原生终态、用量已核对的任务才开放明确续跑。

固定原生回调 `/api/research/internal/data/specialist-control` 沿既有 DataHub 私有控制密钥认证。浏览器不能登记完成或用量；真实执行身份来自插件实际 Agent。`specialist_plan/run/status/cancel` 通过原守卫；直接子 Agent 派生不能绕过协作节点准入及原有四子 Agent配额。

私有账本位于账号根的 specialists 目录，脱离模型可写 workspace，不存第二份聊天正文。节点身份、输入摘要、原生 child ID 先持久预留；紧接原生调用前再持久登记 dispatch。未知提交不重发；完整原生目录缺失、精确父回合终态和未写 dispatch 等见证只能证明未提交，不能将未知请求洗成未提交。

## 取消、恢复和复用

一个节点失败时，其余节点可完成，但正式定稿保持未完成。替换或移除在途节点先请求取消，确认实际终态后才启动替代执行；取消回执不等于停止。超时停止新调用并请求原生取消；未知仍保持未知，不强杀进程。

重启后沿既有会话/子历史和原生模型用量对账，不自动提交模型请求。终态记录区分进程内原生 run ID 与持久历史事件见证；真实助手消息的 Agent/turn/step 与 usage 对应原有请求预留。缺失用量不视为零。

复用成果前重新核验真实证据/产物字节、数据集 manifest 与原始封包、网页原件及出处。变化使相关节点和下游审查失效，历史输出保留。按时完成的资格冻结在 completed_at，不因30分钟后查看历史而失效。

固定研究截止时间；公开时间与实际获取时间分别记录。缺商业授权时仅使用已批准公开来源，保留变化、覆盖和可比性限制；必需证据不足继续拒绝定稿。Quant仅承诺描述性复算，预测/策略回测另行准入。首版不自动读取跨任务记忆。

## 验收与费用

结构化完成及已知用量只是协作必要条件，报告仍走原规范产物和 Host 质量门。缺来源、独立方法读取、计算复核或正式报告均不能自评通过。

新建任务默认未确认200,000保守准入单位、12次原生请求。旧草稿已确认额度保持原值。离线较小请求示例已需48,613预留单位，实际完整工具/历史可能更大；精确用量以原生回执为准。此值不是人民币报价，真实验收须先按所选模型核价并另外确认总费用上限。

本轮不部署、不合并，不调用真实模型。离线合同、实际 Native/Docker行为、干净安装CI和模型质量分别留证；缺任一层证据时不冒充通过。实现细节见[业务账本](../app/research_web/specialists/README.md)和[运行时适配](research-web-specialist-runtime.md)。
