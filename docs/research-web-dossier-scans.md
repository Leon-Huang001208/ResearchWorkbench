# 档案机会与风险扫描

扫描使用当前账户已归档、逐次鉴权并校验 hash 的 DataHub 冻结材料，不采集供应商、不创建研究会话、不执行模型。自动范围限规范身份为 `六位代码.SH/SZ/BJ` 的公司；行业与主题档案可以长期积累材料，但结构化扫描目前返回 `subject_not_covered`。ETF继续关联原组合与行业研究，不获得自动证券匹配。

当前规则产出“财务披露待研究”“公告资料待研究”和有证据的催化剂／风险观察窗口。它们是研究线索，不是买卖结论、收益预测或自动修订的观点。固定方法介绍由UI目录提供，公司／行业研究、调研准备、研报增量、预期差与风险检查最终均准备原DSH草稿，用户发送后执行。盈利调整／预告／风险事件只有通过来源准入且带出处的原生结构化结果才可纳入；小创结果保持clue，未经双源评估不进入正式扫描。

## 证据与状态

列表保留记录类型 `kind=signal`，另以 `signal_type=review|risk|catalyst|opportunity` 供页面筛选；财报与公告归为待研究，不能只因材料出现就标成机会。HTTP列表的kind筛选对应signal_type，rule字段仍保存具体触发规则。

每次最多100份材料，每份最多1000条、完整内部投影最多512KiB。行数、供应商总数、分页完整性、快照状态、观察时点、披露日期和精确证券身份均检查。AKShare财务披露仅对已核验 `akshare-sina-financial-disclosure-v1` 使用 `publication_date`，不把报告期、供应商更新时间或取得时间作为披露日期。财务快照120日、其他30日过期，未来材料拒绝。没有对应规则、资料缺失、截断、撤权和无信号分别显示。

扫描与信号事件使用原SQLite同一事务，失败不推进版本。相同来源／对象／规则／事件合并为一个稳定信号并保留全部证据引用；来源变化产生修订，研究者对未变化信号的处置保持。失去覆盖只标过期，不能推定风险解除；观察项只有同一record_id被研究者明确关闭才产生解除事件。旧观点始终独立保存，扫描不能改写。

HTTP为GET `/api/research/dossiers/signals`、POST `/{id}/scan`、PATCH `/{id}/tracking`。写入沿用expected_revision及幂等键，日期与分页非法返回422。列表重验当前证据状态；详情中的scan保留当次冻结结果与覆盖时点。

## 持续跟踪

默认关闭，无额外守护进程。只有当天合格的手动扫描且当前材料仍可用时才允许开启，默认Asia/Shanghai每日16:30。复用Automation的 `dossier_scan` 原生执行分支，锁定对象与规则源码hash，不允许模型输出格式或MCP工具。规则变更要求新授权，旧同对象日程停用。启用先提交关闭态意图，再创建／启用日程，最后提交激活；失败或中断保持不可运行，重放旧授权不能覆盖后续关闭。

当前调度只重查档案内已有冻结材料及观察窗口，不自动拉取新行情、新闻或小创；新增材料须通过原来源与归档流程。新增、变化、明确解除才有通知事件，无变化设置suppress_delivery，不发例行通知。外部通知仍沿现有已配置频道，本次不配置或发送。

## 保全与验收

档案元数据、引用、pin、scan、tracking与信号索引同库备份／恢复；原文和私有raw保持既有快照位置。私有多用户保全及原资产升级保全纳入档案摘要，忙锁、损坏、符号／硬链接失败关闭，无档案时不初始化文件或改变旧保全结果。没有执行正式恢复、生产数据库操作或常驻部署。

离线测试覆盖真实Snapshots发布／DossierService读取、HTTP路由优先级、幂等、事务失败、撤权、旧授权重放、激活失败恢复、无变化静默、完整备份恢复与删除保护。测试不代表真实来源覆盖、供应商质量、模型研究质量或常驻页面已上线。
