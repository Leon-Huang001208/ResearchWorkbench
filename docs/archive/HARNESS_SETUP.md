# Harness 全自动CI/CD启用指南

## 已完成配置
- 已经在项目根目录创建`.harness/ci.yaml`流水线配置，包含3个阶段：
  1. **代码检查与测试阶段**：自动安装依赖、代码质量扫描、单元测试、接口冒烟测试
  2. **自动部署阶段**：K8s集群滚动部署，零停机更新
  3. **自动处理Issues阶段**：自动识别提交信息中的`Fixes #xxx`标记，自动关闭对应Issues并添加标签

## 启用步骤（只需执行一次）
1. **登录Harness控制台**：https://app.harness.io/
2. **创建新项目**：选择`Continuous Integration`模块，关联GitHub仓库`Leon-Huang001208/Research Workbench`
3. **导入流水线配置**：选择`Import from Git`，导入`.harness/ci.yaml`文件
4. **配置GitHub集成**：在Harness中添加GitHub连接器，授予仓库读写权限
5. **配置K8s连接器**：添加你的K8s集群连接器，配置部署命名空间
6. **开启自动触发**：流水线触发器已经配置为代码提交自动触发，无需手动执行

## 自动执行规则
1. 每次往`master`分支提交代码，自动触发全流水线执行
2. 单元测试覆盖率低于80%会自动终止流水线，阻止部署
3. 冒烟测试不通过会自动回滚，不影响线上服务
4. 提交信息中包含`Fixes #<issue号>`的，会在部署成功后自动关闭对应Issue，添加`✅ 已完成`标签

## 当前Issues自动处理规则
所有现有Issues处理完成后，提交代码时在提交信息中添加对应的Fixes标记即可自动关闭：
- 完成Issue #40：提交信息添加`Fixes #40`
- 完成Issue #39：提交信息添加`Fixes #39`
- 以此类推
