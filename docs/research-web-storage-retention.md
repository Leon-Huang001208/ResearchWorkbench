# RWB 测试与任务证据留存

目标是让可再生文件尽快退出磁盘，同时保留足以证明交付、恢复和失败原因的最小证据。目录大小只是逻辑占用；每次回收另记录 `df` 的物理空间变化，不能把 `du` 直接写成释放量。

| 类别 | 处理时点 | 保留内容 |
| --- | --- | --- |
| 成功 pytest 的 `--basetemp` 与模拟业务数据 | 实际退出码、同批 JUnit/stdout/stderr 及目录身份核验后，立即回收 | 任务、候选 SHA、批次/用例、目录 inode、运行与回收回执；不等 PR 合并 |
| 成功测试的完整 stdout/stderr | 最终收尾前逐文件分类；只允许同批通过回执明确列出的输出不进入长期归档 | JUnit、批次运行/回收回执、最终报告及来源 hash |
| 重复下载物和中间截图 | 先只读盘点和确认用途，再按精确范围处理 | 不能借任意测试 PASS 自动删除；必要视觉/来源证据保留 |
| 已结束的失败、取消或容量终止 | 保存简短真实失败记录，确认本任务根身份和无占用后默认清理可再生根 | 实际退出码、结果、JUnit 是否存在及必要日志；owner 已回收但 outcome 为 failed，不伪报 PASS |
| 执行、根身份或占用未知 | 查明前不删除 | 当前现场和必要记录；业务原件、其他任务资源继续保护 |
| 合并任务的最终证据 | 各工作树按选择清单归档，单任务合计保留集上限 128 MiB | exact SHA/tree、验证计划和回执、独立评审、CI 与平台身份、必要现场证据 |
| Git 恢复点、生产恢复档案和业务数据 | 使用各自的受管保全与恢复校验规则 | 新登记且完成交付的普通 Git 恢复点经原保护检查后可不等 7 天轮转，始终保留最新 2 个验证通过的点；未登记历史逐类审核，生产恢复与业务数据不由本规则清理 |
| Docker 镜像、卷、BuildKit 缓存 | 复用 `rwb-docker` 锁与现有 20 GiB 构建缓存预算 | 当前和上一通过镜像、运行服务、业务卷及租约继续保护；不手删 blob 或 `Docker.raw` |

## 每批测试的临时根

每个任务同一时间只运行一批 pytest；批次结束后按真实结果、根身份和占用情况回收，再继续下一批。日常使用 `run`，它亲自启动 pytest 并把实际退出码、冻结的最多20个用例和结果写在根外，不依赖手工填写“通过”。默认exact模式核对当前Git HEAD与干净工作树，并固定子进程cwd；示例中的`TASK`和候选SHA必须替换为本任务真实值。未提交的红绿循环显式加`--mode wip`：回执的`exactCheckout=false`，不能当最终候选测试。命令只用于已有Python的离线测试，不安装包、不启动模型或Docker：

```bash
python scripts/test_artifact_retention.py run \
  --parent /private/var/tmp \
  --receipt logs/TASK/batch-01-lease.json \
  --task-id TASK --candidate 40位候选SHA \
  --batch-id batch-01 \
  --node-id tests/research_web/test_example.py::test_case
```

该批会在 `logs/TASK/` 留下实际生成的 JUnit、stdout/stderr、`batch-01.result.json` 和根回执；未生成 JUnit 就记录缺失。低级 `create/admit/retire` 只供受审执行器或中断恢复，`retire` 使用原工具生成的 `--result`。成功回收继续核对同批 PASS、外部证据 hash、目录身份、无占用及原隔离删除条件；不能用旧 PASS JUnit 代替本批结果。普通失败采用下一节的简短失败记录与清理路径，不要求先获得同批 PASS 或完整目录树 hash。工具在起跑前及运行期间约每秒检查512MiB根、64MiB输出和3GiB空间门；超限时终止并等待自己的 pytest 执行结束，再检查该根占用。`run` 仍返回非零，不自动重跑。

## 失败后保全并继续验证

保留的是简短真实失败记录，不默认保留完整临时根。普通失败或容量终止后，确认自己的执行已结束、
登记根身份匹配且无占用，就清理本任务可再生根；owner 记为已回收且 `outcome=failed`。
实际非零退出码、结果、JUnit 缺失和必要日志保持原事实，不把清理当作测试通过，也不由后续 PASS 覆盖旧失败。
这类清理与错误修正后的继续执行无需逐次确认，不要求整棵根的逐文件 hash 或恢复副本。

确需保留复现现场时，运行时显式加 `--keep-failed REASON`，写明保留用途；用途结束后按原身份和无占用条件清理。
身份不明、仍在执行或占用的目录、业务原件及其他任务资源不删除。若多个夹具累计超限，缩小批次或将重夹具逐项运行；
源码修正后绑定新候选，沿同一任务继续，不重开任务、退款或清零历史累计。
512MiB根、64MiB输出、3GiB宿主余量和最多20个用例保持，新增依赖、付费调用、服务和部署仍按各自授权处理。

## 最终日志选择

运行中的夹具可能正常删除已经完成的子目录。容量遍历仅容忍登记根内子路径的
`ENOENT`，扫描前后仍核对根的目录类型、设备与 inode；根缺席、替换、权限或 IO
错误继续拒绝。此兼容不改变 512MiB 根、64MiB 输出和 3GiB 空间门，也不替代
执行结束后的身份与无占用核对。对应独立缺陷复现和负例见本次容量探针任务报告。

新登记的交付任务在每个需归档的 `logs/` 目录放置 `evidence-retention.json`。清单逐文件覆盖现存内容；它自己自动保留。历史任务缺该模式时沿旧全量合同，不因升级默默删除。示例：

```json
{
  "schemaVersion": 1,
  "keep": ["localReceipt.json", "batch-01.xml", "batch-01-lease.json", "batch-01.result.json", "batch-01.stderr"],
  "discard": [
    {
      "path": "batch-01.stdout",
      "sha256": "该文件的64位SHA-256",
      "proof": "batch-01.xml",
      "proofSha256": "JUnit文件的64位SHA-256",
      "batchReceipt": "batch-01-lease.json",
      "batchReceiptSha256": "退休回执的64位SHA-256"
    }
  ]
}
```

`keep` 中必须包含最终报告、审查、批次/退出码回执及不可替代的失败材料；`discard` 只接受同批退休回执明确列出的 stdout/stderr。最终回执、失败/未知记录、恢复材料、下载副本和截图不能借别批 PASS 自动丢弃。缺清单、漏列文件、证明失败、批次不符或哈希变更，收尾保持 `blocked` 且源文件不删。全部工作树的保留集合计超过 128 MiB 时先去重或单独审查必要性，不靠提高上限继续积累。源目录删除前，归档副本会用保留的相对清单重验批次/退出码/JUnit语义；历史源绝对路径不作为唯一可复核依据。

选择性归档只是 Git 收尾前可复核的暂存。Git 最终认证完成且原恢复、资源和占用保护门均通过后，既有 `resource_lifecycle.mjs` 把本任务已归档的临时验证日志登记为退休事件，保存有界摘要，再删除完整临时目录；`cleanup_pending` 或保护门未通过时保留目录，等待后续受管事件补清。代码内任务报告、Git common 收尾回执、正式报告、业务数据及生产恢复原件不随临时日志退休。

历史日志和未归并工作树先做只读清单：核对登记身份、进程/打开文件、Git 状态、外部证据 hash 与恢复引用。已合并任务的重复中间产物可按确认的清单回收；未登记或用途不明的文件保留并登记复核责任，不再把它们自动解释为永久必要证据。例外记录归属、用途、容量和下次复核日期。最终资源/Git 收尾仍走受管入口；早期测试临时根回收不改变 PR、CI 或部署状态。
