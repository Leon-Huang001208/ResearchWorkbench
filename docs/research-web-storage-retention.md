# RWB 测试与任务证据留存

目标是让可再生文件尽快退出磁盘，同时保留足以证明交付、恢复和失败原因的最小证据。目录大小只是逻辑占用；每次回收另记录 `df` 的物理空间变化，不能把 `du` 直接写成释放量。

| 类别 | 处理时点 | 保留内容 |
| --- | --- | --- |
| 成功 pytest 的 `--basetemp` 与模拟业务数据 | 实际退出码、同批 JUnit/stdout/stderr 及目录身份核验后，立即回收 | 任务、候选 SHA、批次/用例、目录 inode、运行与回收回执；不等 PR 合并 |
| 成功测试的完整 stdout/stderr | 最终收尾前逐文件分类；只允许同批通过回执明确列出的输出不进入长期归档 | JUnit、批次运行/回收回执、最终报告及来源 hash |
| 重复下载物和中间截图 | 先只读盘点和确认用途，再按精确范围处理 | 不能借任意测试 PASS 自动删除；必要视觉/来源证据保留 |
| 失败、取消、未知受理 | 先保留最小复现根、原失败回执和关键原始输出；修复通过后重新审查 | 不因新一次 PASS 覆盖旧失败或自动重试付费工作 |
| 合并任务的最终证据 | 各工作树按选择清单归档，单任务合计保留集上限 128 MiB | exact SHA/tree、验证计划和回执、独立评审、CI 与平台身份、必要现场证据 |
| Git 恢复点、生产恢复档案和业务数据 | 使用各自的受管保全与恢复校验规则 | 新登记且完成交付的普通 Git 恢复点经原保护检查后可不等 7 天轮转，始终保留最新 2 个验证通过的点；未登记历史逐类审核，生产恢复与业务数据不由本规则清理 |
| Docker 镜像、卷、BuildKit 缓存 | 复用 `rwb-docker` 锁与现有 20 GiB 构建缓存预算 | 当前和上一通过镜像、运行服务、业务卷及租约继续保护；不手删 blob 或 `Docker.raw` |

## 每批测试的临时根

每个任务同一时间只保留一个活动根；一批完成并回收后再创建下一批。日常使用 `run`，它亲自启动 pytest 并把实际退出码、冻结的最多20个用例和各证据hash写在根外，不依赖手工填写“通过”。默认exact模式核对当前Git HEAD与干净工作树，并固定子进程cwd；示例中的`TASK`和候选SHA必须替换为本任务真实值。未提交的红绿循环显式加`--mode wip`：只回收临时夹具，回执的`exactCheckout=false`，不能当最终候选测试或自动丢弃日志。命令只用于已有Python的离线测试，不安装包、不启动模型或Docker：

```bash
python scripts/test_artifact_retention.py run \
  --parent /private/var/tmp \
  --receipt logs/TASK/batch-01-lease.json \
  --task-id TASK --candidate 40位候选SHA \
  --batch-id batch-01 \
  --node-id tests/research_web/test_example.py::test_case
```

该批会在 `logs/TASK/` 留下 `batch-01.xml`、`batch-01.stdout`、`batch-01.stderr`、`batch-01.result.json` 和回收后的 lease。低级 `create/admit/retire` 只供受审执行器或中断恢复；`retire` 还必须传入工具实际运行生成的 `--result`，不能手工用旧PASS JUnit代替。工具只接受登记过的同inode根、同任务/候选/批次/用例、外部证据、实际退出码0、无打开文件和安全目录树。同任务的创建、准入与退休共用父目录锁；根内硬链接只有全部链接都位于该根内才可回收，外部链接、符号链接证据、被替换目录、失败/未知结果都阻止删除。隔离后和重入前重新核对每个路径的类型、inode、大小与内容hash；只读目录只在已隔离的本任务根内恢复写权限。工具在起跑前及测试运行期间约每秒检查512MiB根、64MiB输出和3GiB空间门，超限中断并等待自己的pytest进程组，流式限量写失败回执、保留现场，不自动重跑。

## 最终日志选择

新登记的交付任务在每个需归档的 `logs/` 目录放置 `evidence-retention.json`。清单逐文件覆盖现存内容；它自己自动保留。历史任务缺该模式时沿旧全量合同，不因升级默默删除。示例：

```json
{
  "schemaVersion": 1,
  "keep": ["localReceipt.json", "batch-01.xml", "batch-01-lease.json", "batch-01.result.json", "batch-01.stderr"],
  "discard": [
    {
      "path": "batch-01.stdout",
      "sha256": "该文件的64位SHA-256",
      "proof": "batch-01.xml",
      "proofSha256": "JUnit文件的64位SHA-256",
      "batchReceipt": "batch-01-lease.json",
      "batchReceiptSha256": "退休回执的64位SHA-256"
    }
  ]
}
```

`keep` 中必须包含最终报告、审查、批次/退出码回执及不可替代的失败材料；`discard` 只接受同批退休回执明确列出的 stdout/stderr。最终回执、失败/未知记录、恢复材料、下载副本和截图不能借别批 PASS 自动丢弃。缺清单、漏列文件、证明失败、批次不符或哈希变更，收尾保持 `blocked` 且源文件不删。全部工作树的保留集合计超过 128 MiB 时先去重或单独审查必要性，不靠提高上限继续积累。源目录删除前，归档副本会用保留的相对清单重验批次/退出码/JUnit语义；历史源绝对路径不作为唯一可复核依据。

历史日志和未归并工作树先做只读清单：核对登记身份、进程/打开文件、Git 状态、外部证据 hash 与恢复引用。已合并任务的重复中间产物可按确认的清单回收；未登记或用途不明的文件保留并登记复核责任，不再把它们自动解释为永久必要证据。例外记录归属、用途、容量和下次复核日期。最终资源/Git 收尾仍走受管入口；早期测试临时根回收不改变 PR、CI 或部署状态。
