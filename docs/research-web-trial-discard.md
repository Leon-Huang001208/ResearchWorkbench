# Historical trial retirement: offline preservation helper

`research_workbench_entrypoint.resident.trial_discard_backup` provides a bounded preview and an exact-file, same-filesystem backup for a separately authorized retirement of historical trial sessions. It is a library for the existing resident maintenance transaction, not a deploy command or a deletion engine.

The caller must already hold the resident maintenance exclusion fence, establish exact account ownership, and prove that the verified old Host is stopped with no remaining writers before backup or retirement. The helper does not infer this from `active: null` or any other Host status. `preview(home)` reads the primary `research-web/index.json`, `server/accounts.sqlite3`, `server/resident.json`, and every registered account's `server/users/<UUID>/research-web/index.json` when present. It returns IDs, counts, known status labels, file identities and hashes, and a seal. Missing private roots and indices are explicit. It rejects unknown directories, malformed mapping, symlinks, oversized files, more than 64 account roots, more than 512 MiB of aggregate source files, and a SQLite journal/WAL. The database query is immutable and read-only after journal exclusion. No model values, credentials, or session bodies are returned.

`backup(home, backup_parent, expected_seal)` requires a protected `0700` backup parent on the same filesystem, no symlinked ancestor, at least 2 GiB of free space after reserving twice the aggregate source bytes, and an unchanged preview seal. Free space is measured from the pinned backup-parent directory descriptor. Creation uses pinned directory descriptors and no-follow, exclusive file creation. It copies the account database, binding record, and each present owned index, verifies every copied byte and mode, then restores each copy into an isolated temporary file and compares bytes and mode again. Files and touched directories, including the manifest and backup parent, are synced before the receipt. The saved `manifest.json` contains expected file hashes, sizes, modes, and the source seal; the receipt includes its SHA-256. A drift, directory swap, low-space condition, failed sync, or partial copy refuses the operation. A partial backup remains protected for inspection and never receives a successful receipt. Because model settings are contained in the business indices, full index bytes preserve them while the preview exposes only a settings hash.

This helper does not remove sessions, clear Wind `UNKNOWN` markers, alter account or model configuration, stop or start processes, take the maintenance fence, establish idle, or grant deployment. It backs up only the database, binding, and business indices. It does **not** back up `sessions/`, `runtime/home/sessions/`, dossiers, or other session artifacts covered by the full preservation scope. The caller must bind the sealed backup receipt to its maintenance journal and separately preserve any artifact it plans to retire, with a proven restoration path. A `restore_verified` receipt proves only this backup's byte and mode recovery; it is not live restore, deployment, or product acceptance evidence. The exact live state and actual restored behavior require separate verification.
