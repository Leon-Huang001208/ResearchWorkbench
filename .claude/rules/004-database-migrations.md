# 数据库迁移规范

## 概述

AlphaFoundry 使用 Alembic 管理 PostgreSQL 数据库架构变更，确保迁移可追踪且可回滚。

---

## Alembic 配置

### 配置文件位置

- `storage/migrations/alembic.ini` - Alembic 配置文件
- `storage/migrations/env.py` - 环境配置

### 基本命令

```bash
# 进入迁移目录
cd storage/migrations

# 创建新迁移
alembic revision -m "description of change" --autogenerate

# 升级到最新版本
alembic upgrade head

# 升级到特定版本
alembic upgrade <revision_id>

# 降级到上一版本
alembic downgrade -1

# 降级到特定版本
alembic downgrade <revision_id>

# 查看当前版本
alembic current

# 查看迁移历史
alembic history --verbose
```

## 迁移文件命名

### 自动生成

使用 `--autogenerate` 时，Alembic 自动生成文件名：
```
<timestamp>_<short_description>.py
```

### 手动命名约定

对于手动创建的迁移，使用描述性名称：
- `add_table_<table_name>`
- `add_column_<table>_<column>`
- `modify_column_<table>_<column>`
- `create_index_<index_name>`
- `drop_table_<table_name>`

**示例**：
```
20240504_001_add_asset_snapshot_table.py
20240504_002_add_confidence_column_to_signals.py
```

## 迁移编写规范

### 自动生成的迁移

使用 `--autogenerate` 时，务必检查生成的迁移文件：

```python
"""add asset snapshot table

Revision ID: abc123
Revises: def456
Create Date: 2024-05-04 10:00:00.000000

"""
from alembic import op
import sqlalchemy as sa

# revision identifiers, used by Alembic.
revision = 'abc123'
down_revision = 'def456'
branch_labels = None
depends_on = None

def upgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    op.create_table(
        'asset_snapshot',
        sa.Column('snapshot_id', sa.String(), nullable=False),
        sa.Column('canonical_id', sa.String(), nullable=False),
        sa.Column('as_of', sa.DateTime(timezone=True), nullable=False),
        sa.PrimaryKeyConstraint('snapshot_id')
    )
    # ### end Alembic commands ###

def downgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    op.drop_table('asset_snapshot')
    # ### end Alembic commands ###
```

### 数据迁移

对于数据迁移，在迁移文件中实现：

```python
def upgrade() -> None:
    # 架构变更
    op.add_column('signals', sa.Column('confidence', sa.Float(), nullable=True))
    
    # 数据迁移（如需要）
    op.execute("""
        UPDATE signals 
        SET confidence = 0.5 
        WHERE confidence IS NULL
    """)

def downgrade() -> None:
    op.drop_column('signals', 'confidence')
```

## 回滚策略

### 每个迁移必须可回滚

确保 `downgrade()` 函数可以正确撤销 `upgrade()` 的变更。

### 破坏性变更

对于破坏性变更（如删除表或列），考虑：

1. 先发布一个版本标记数据为过时
2. 确认所有代码不再使用后再删除
3. 保留备份或归档

---

## 迁移检查清单

创建迁移前确认：
- [ ] 已在开发环境测试迁移
- [ ] `upgrade()` 和 `downgrade()` 都能正常工作
- [ ] 迁移不包含敏感数据
- [ ] 迁移描述清晰准确
- [ ] 数据迁移考虑了性能（大量数据时使用分批处理）

运行迁移前确认：
- [ ] 已备份数据库
- [ ] 在 staging 环境测试过
- [ ] 已确认回滚方案可用
