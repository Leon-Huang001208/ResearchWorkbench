# 研报增量分析

## 使用边界

- 只处理能读取完整正文的卖方研报或研究文章，聚焦增量、公开时序、可信度、传导链和证伪。
- 只需通读、摘要、表格提取或格式转换时，使用 `document-reading`，不触发本能力。
- 默认在聊天中回答。只在用户明确要求文件且 Runtime 实际暴露相应工具时，才生成 Markdown、HTML、DOCX 或 XLSX。DataHub 也只在 Runtime 实际暴露时使用。

## 流程

1. 记录标题、机构或公众号、作者（如可见）、首次发布时间、资料类型与分析截止时间。按 `references/evidence-protocol.md` 分开事实、来源观点、新增证据和研究推断。
2. PDF 只通过 `research_run_script` 中的 `research_helpers.read_pdf`读取，例如 `from research_helpers import read_pdf`。保留 `p.N` 页码定位；空文本页标为需要 OCR，不猜测内容。
3. 公开网页或微信文章必须得到完整可见正文并保留段落顺序。搜索摘要只是找原文的线索，不是原文证据。正文、决定性来源或附件打不开时，直接输出“证据不足”或“无法判断”，并请用户提供 PDF 或复制正文。
4. 根据 `references/methodology.md` 建立证据账本和比较基线。没有可核验基线时只称“本篇新增”，不宣称“市场新增”或“预期差”。
5. 用 `web_search` 查找时点在研报首发之前的候选来源；只把实际打开并核验的正文放入公开时序。无实时工具时，公开新增性标记为“无法判断”。
6. 双向检查主张与反证，说明范围、样本、口径、时滞、替代解释、验证指标和失效信号。
7. 若需结构化结果，按 `references/output-schema.md` 组织 JSON，用 `scripts/validate_digest.py` 校验。脚本是当前能力版本的只读资源，由 `research_run_script` 在会话沙箱内加载。
8. 可读图片附件可作原图证据。v1 不裁剪 PDF 原页；只有当每条关系都有来源定位时，才用 `scripts/render_knowledge_graph.py` 生成“据研报重绘”SVG。不能形成可靠关系时写明“视觉证据受限”，不生成图。

## 条件化研究判断

“现在行动”、“降低暴露”、“退出条件触发”等标签只能描述研报对某行业或对象的条件化研究含义。必须同时列出：

- `研报明示` 或 `研报隐含`；
- 适用对象、时间窗、触发条件与来源定位；
- 关键假设、验证指标和失效信号。

不推断用户持仓，不给个人仓位、买卖或收益承诺。条件不齐时，只列证据与待验证问题。

## 默认输出

1. 证据可用性与分析基线。
2. 不超过五项增量：内容、证据类型、来源定位、公开时序、会改变什么判断。
3. 主张、反证、传导链、情景、催化、失效信号与待核查项。
4. 非个性化的条件判断，或在证据不足时的“无法判断”。
