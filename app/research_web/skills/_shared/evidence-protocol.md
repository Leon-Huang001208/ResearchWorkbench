# 研究证据协议

本协议是内置研究能力随版本固化的只读证据约束，不是可单独调用的 Skill，也不授予工具、联网、文件或宿主权限。

## 1. 来源层级与可用性

按以下优先级选取并标记来源，低层级材料不能无说明地替代高层级材料：

1. 一手正式来源：监管或政府文件、交易所与公司公告、法定披露、正式统计、会议原文和可核验数据集。
2. 一手补充来源：公司官网材料、管理层公开发言、产品或机构正式页面。
3. 有编辑责任的二手来源：研究机构报告、主流媒体、行业协会与专业数据库。
4. 其他线索：转载、聚合页、社交内容和搜索结果摘要。

搜索结果摘要只用于发现候选来源，不能当作原文证据。若决定性来源无法打开、正文不完整或关键附件不可读，必须写明“证据不足”或“无法判断”，不得用摘要、常识或模型记忆补齐。

## 2. 证据分层

每项关键结论都要能区分：

- 事实：来源直接披露且可定位的内容。
- 来源观点：来源作者、机构或发言人的判断，不等于已发生事实。
- 新增证据：相对既定基线，新出现且可能改变判断的信息。
- 研究推断：由已列证据推导的解释，明确推理链、假设和不确定性。

不得把传闻写成事实、把来源观点写成共识、把相关性写成因果，或把推断伪装成来源原话。

## 3. 日期、口径与基线

- 对事件注明发生时间、首次披露时间和检索截止时间；三者不同时分别列出。
- 对数值注明期间、频率、单位、币种、是否含税或复权、样本和计算方法；不同口径不得直接比较。
- 在讨论“超预期”“变化”“新增”前先定义基线，例如此前公告、上一报告期、公开一致预期或事件发生前可获得的信息集。
- 只使用在对应时点已经公开的证据，避免以后见之明改写当时判断。

## 4. 反向证据与冲突

主动寻找能够削弱主结论的证据，包括相反数据、替代解释、执行约束、时间错配和来源利益关系。来源冲突时并列呈现各自主张、日期、口径与证据等级；没有足够依据裁决时明确保留分歧，不做虚假折中。

## 5. 情景与失效信号

情景分析至少说明触发条件、传导链、观察窗口和可验证信号。结论应给出失效条件或需要更新判断的信号。没有可靠概率依据时使用条件化情景，不编造精确概率。

## 6. 工具与交付边界

- 只调用当前 Runtime 实际暴露的工具。DataHub 或文件生成工具未暴露时，不调用、不重试，也不假定其存在。
- 默认先在聊天中回答。仅当用户明确要求文件且 Runtime 暴露相应工具时，生成 Markdown、HTML、DOCX 或 XLSX，并核验实际产物；否则说明限制。
- 工具返回的摘要、片段或数据必须保留来源、日期、口径与缺失说明。工具不可用不构成编造数据的理由。

## 7. 非个性化研究边界

输出是研究判断，不是面向个人的仓位、买卖或收益承诺。涉及行动含义时，必须采用条件化表达，注明适用对象、时间窗、触发条件、来源定位、关键假设和失效信号；无法满足这些条件时只陈述证据与待验证问题。
