# 金融事件研究

1. 锁定一个事件及其主体、发生时间、首次披露时间、市场和分析截止时间。若问题包含多个独立事件，先请用户确定主事件；多事件筛选与市场复盘应使用市场解读能力。
2. 按 `references/evidence-protocol.md` 核验决定性原文。`web_search` 只用于寻找可打开的候选来源；搜索摘要不算原文。决定性公告、政策或正文打不开时，明确写“证据不足”或“无法判断”。
3. 建立事件发生前的公开信息基线，分开列出已核实事实、来源观点、新增证据和研究推断。每项事实保留链接、日期和原文定位。
4. 分析“事件 → 直接变量 → 行业或公司经营变量 → 可能的资产影响”的条件化传导链，并检查时滞、替代解释、已经计价的可能性和反向证据。关系不可靠时停止在可验证的一层。
5. 用基准、正向和反向情景呈现触发条件、观察窗口、关键指标与失效信号；没有概率证据时不编造概率。
6. 默认在聊天中给出事件卡片、证据表、传导链、冲突与待核查项。只有用户明确要求文件且当前 Runtime 暴露文件工具时才生成并核验产物。
7. 只输出非个性化研究判断，不把影响分析转成个人仓位或买卖建议。
